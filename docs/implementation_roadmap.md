# DormTopology 3D 项目实施方案

本文是首版范围、架构、分工和工期的唯一基线。**硬约束：4 人小队在 48 小时内交付比赛原型。** 数据格式见[数据契约](data_contract.md)，交互见[UX 设计](ux_design.md)，具体完成条件见[任务清单](project_tasks.md)。所有功能当前均待实现。

2026-10-16 按用户要求合并附件 `tasks.md`：两种走线策略、4/6/8 位插排、四格书架与右侧抽屉、桌体 GLB 和前端接口验收均纳入首版。新增范围增加了原 48 小时计划的交付压力；以下排期为目标，未完成项必须保留并报告，不能通过降级宣称完整验收通过。

团队调整为 4 人，物品布局算法与走线算法分成两个独立任务，由 C、D 分别完成；A、B 分别负责前端和后端。两项算法各有独立验收和交付，先基于共同场景并行开发，再进行布局应用后的走线联调。

## 1. 目标与边界

首版闭环：照片辅助建模 → 用户校正 → 推荐整理 → 确认接线 → 自动走线 → 前后对比与执行指南。

多模态模型负责识别与理解，Rodin 负责生成外观，几何算法负责尺寸、摆放和路径验证。首版面向一个经过配置的宿舍桌面，不处理任意场景精确重建。

| 功能 | 48 小时必须交付 | 可选或后续扩展 |
| --- | --- | --- |
| 场景 | 一个标准桌体 GLB，桌面、上层四格书架与右侧抽屉支撑面，简化碰撞体 | 多模板、交互式家具结构编辑、抽屉开合 |
| 照片识别 | 测试照片的可编辑物品清单、手动补标和尺寸确认 | 多视角、遮挡恢复与分割优化 |
| Rodin | 提供 1–2 个独立单品 GLB，至少 1 件真实任务完成生成、下载与显示替换；失败时保留简化模型 | 并发生成更多物品、复杂资产管理 |
| 整理 | 8 件待整理物品，外设保留桌面中央、杂物分配至书架或抽屉，多平面贪心摆放，0°/90° 朝向，手动调整与冲突提示 | 自由堆叠和局部搜索优化 |
| 走线 | 3 根线，表面取点，粗细线参数，穿线孔与背板后双策略，4/6/8 位插排选择与多线汇聚，路径搜索及曲线复查 | 线束动画 |
| 交付 | 同视角前后切换、简单归位动画、指标与可导出的执行指南 | 滑动对比、游戏化、AR、打印配件 |
| 终端 | 电脑浏览器完成全部流程，手机支持图片上传、预览及场景与结果查看 | 手机完整编辑流程 |

尺寸默认值是演示配置，来源与解释集中在数据契约。照片中的位置和尺寸由用户校正，不承诺毫米级重建或整桌模型秒级生成。路径结果是满足已建模约束的建议，不作为电气安全认证。

演示计数按用户确认：8 件仅指待整理物品，插排、墙插和网口等基础设备另计；3 根线包含插排总线。基础设备仍进入统一场景、碰撞检查和算法结果，不能因另计而省略。H0–H4 固定共同样例的完整 ID 清单和连接表。

## 2. 系统结构与职责

```mermaid
flowchart TD
    A[照片上传与框选] --> B[识别清单与用户校正]
    B --> C[版本化场景与简化碰撞体]
    B --> D[Rodin 后端异步任务]
    C --> E[多平面整理]
    E --> F[用户确认接口与线长]
    F --> G[路径搜索及平滑后复查]
    G --> H[对比与执行指南]
    D --> I[按物品 ID 替换显示模型]
    C --> I
```

| 负责人 | 模块边界 | 交付 |
| --- | --- | --- |
| A：3D 前端 | UI、照片补标、简化场景、物品与接口编辑、模型加载、结果展示 | 可操作的电脑端界面和手机上传、预览、查看能力 |
| B：识别与生成后端 | 图片处理、多模态识别、Rodin 适配、任务持久化、场景保存、指南生成 | 识别与生成服务、资产文件、有效版本的指南 |
| C：物品布局算法 | 多平面摆放、布局硬约束、共享物品几何、连续可用面积与布局冲突 | `packing_result.json`、布局失败案例与验收记录 |
| D：走线算法 | 双策略路径搜索、连接兼容、曲线和线缆体积校验、暴露线长与走线冲突 | `cable_routing.json`、走线失败案例与验收记录 |

A 主责桌体运行时资产，C 核验支撑面和物品碰撞几何，D 核验穿线孔与背板后通道。Rodin 由 B 统一接入，A 不直接调用供应商接口，C、D 均不等待展示资产。

### 算法任务交接

- B 负责入口结构、协议版本和 ID 引用校验，分别调用 C、D 的算法函数；C、D 各自负责本任务的几何和业务约束校验，沿用数据契约的结果与错误码。
- C 主责共享坐标变换、物品包围盒和几何容差规则，D 共同核验并复用；D 主责线缆扫掠体积、曲率和通道净空检查。H0–H4 确认最小函数接口与样例，不引入通用几何框架。
- C 输入已确认的当前场景，输出完整物品布局；A 预览并提交接受操作，由 B 原子应用有效布局和递增版本，D 再输入更新后的场景、接口和线缆。两项输出均携带输入场景 ID 与版本；D 不直接修改 C 的布局，也不自动循环请求重新摆放。
- D 可从 H4 起用共同场景独立开发，无需等待 C 完成布局算法。C、D 分别提供正常与失败案例给 B、A 联调，H16–H28 完成实际布局后的重新走线。

H0–H4 冻结以下最小 Python 函数入口，由 `domain` 模型直接传参和返回，不经 HTTP 或磁盘；它们是待实现接口，数据字段只按数据契约定义：

| 负责人 | 入口 | 语义 |
| --- | --- | --- |
| C | `plan_packing(scene) -> PackingResult` | 生成建议，覆盖全部物品，保留输入版本，不修改输入 |
| C | `validate_layout(scene) -> LayoutCheck` | 返回 `geometry_valid` 布尔值及 `issues`；区分几何硬约束和未达成的收纳目标，供编辑提交、布局应用与指南复查复用 |
| C | `measure_free_area(scene) -> float` | 按契约固定网格计算一个场景的主桌面连续可用面积 |
| D | `plan_routing(scene) -> RoutingResult` | 对全部请求线缆规划，保留输入版本，不修改输入 |
| D | `validate_routing(scene, result) -> list[Issue]` | 复核输入标识、端点、同一曲线的体积、长度、弯曲和线缆间占用 |
| D | `measure_exposed_length(scene, result=None) -> float 或 None` | 有结果时统计同版本已验证曲线；无结果时统计该快照的原始折线。任一请求路径缺失或失败时返回 `None` |

`Scene`、两类结果、`Issue` 与 `LayoutCheck` 均由 `domain` 定义，B、C、D 共用，不各自复制一套字段。`LayoutCheck` 是内部领域检查对象，不新增对外状态枚举；`geometry_valid` 为真但仍有未收纳物品时可以形成 `partial`。共享几何入口至少覆盖局部/世界点和方向变换、旋转物品碰撞、支撑面与边界检查，C 给出带数值的样例供 D 核对。

### 技术选择

2026-10-16 经用户确认，首版后端固定使用 Python + FastAPI。项目部署于 Web，浏览器通过 HTTP API 访问后端；Web 部署不改变此选型。Node.js 可用于前端开发与构建工具，不作为首版应用后端，也不新增 Node.js 中间服务。

- 前端：React + TypeScript、Three.js / React Three Fiber 与 Drei；场景状态集中管理。
- 后端：Python + FastAPI、SQLite 与本地文件；由后端暴露应用接口。C 的布局算法、D 的走线算法及共享几何以 Python 模块交付，由 B 直接调用函数，保持单一后端服务。
- 异步生成：后端受限后台任务加数据库状态，前端轮询；重启后已有供应商标识的任务恢复查询，尚未提交与提交结果未知的任务按下文恢复规则处理。首版不引入独立消息队列。同步算法与阻塞 I/O 不直接占用异步路由的事件循环，通过有并发上限的执行器运行。
- Rodin：通过 HTTP 适配器接入。B 在前 4 小时实测账户可用的版本与提交、查询、下载流程并记录结果；不把尚未核验的端点或供应商任务字段写作既定契约。

API 密钥保留在后端。模型生成失败、超时或限流时，简化场景、整理与走线继续可用；缓存必须标注来源。

### 分层与依赖方向

2026-10-16 参考用户提供的架构图，将“领域规则、流程编排、接口、数据存取”分开，并通过依赖倒置和统一装配连接。下述目录和接口职责是开始编码时的设计基线，尚未创建；保持一个 FastAPI 后端进程，不增加部署单元。

| 层 | 本项目职责 | 依赖边界 |
| --- | --- | --- |
| `domain` 领域规则 | 场景、物品、接口和线缆模型；坐标变换、布局与走线算法、硬约束、结果有效性规则及领域错误 | 不导入 FastAPI、SQLite、文件存储或供应商 SDK，不进行网络与持久化 I/O |
| `service` 编排流程 | 读取场景、调用规则与算法、应用有效布局、使旧结果失效、提交生成任务、汇总指标与生成指南 | 依赖 `domain` 和本层声明的最小能力接口，通过注入对象调用存储与外部服务 |
| `api` 接口 | HTTP 参数解析、结构和协议版本检查、调用 service、序列化响应及统一映射 HTTP 错误 | 依赖 `service`，可引用领域类型做转换；不直接执行 SQL、访问供应商或实现几何规则 |
| `db` 数据存取 | SQLite 场景、快照、结果与任务读写，事务及版本条件更新 | 实现 service 声明的存储接口，可引用领域数据类型；不决定布局、走线或任务业务规则 |

识别、Rodin HTTP 与本地资产文件操作放在外部适配器 `adapters`，与 `db` 一样实现 service 所需的接口。供应商字段在适配器内转换为内部任务与结果，避免扩散到算法或浏览器。框架和存储变化时，领域规则仍可独立运行。

```mermaid
flowchart TD
    Bootstrap[bootstrap 统一装配] --> API[api HTTP 接口]
    Bootstrap --> Service[service 流程与能力接口]
    Bootstrap --> DB[db SQLite 实现]
    Bootstrap --> Adapters[adapters 外部服务与文件实现]
    API --> Service
    Service --> Domain[domain 模型、规则与算法]
    DB -. 实现 service 的存储接口 .-> Service
    Adapters -. 实现 service 的能力接口 .-> Service
```

箭头表示代码依赖，虚线表示接口实现；运行时 service 调用注入的对象。service 不反向导入 `db` 或具体适配器，`domain` 不依赖外层。能力接口可用 Python `Protocol` 声明，只为存储、识别、生成和文件操作等需要隔离的 I/O 边界建立；C、D 的确定性算法直接调用函数，不逐个包装接口或基类。

### 建议工程布局与统一装配

```text
frontend/src/
  api/                 HTTP 客户端与契约数据转换
  state/               当前场景、原始快照、版本及异步结果接收
  scene/               Three.js 场景、交互与外观替换
  ui/                  流程界面与结果展示
backend/app/
  domain/
    models.py          与数据契约对应的领域数据类型
    errors.py          沿用契约错误码的领域错误
    rules.py           ID 引用、场景变更与结果有效性规则
    geometry/          C 主责的共享变换与物品碰撞几何
    packing/           C 的布局算法与面积指标
    routing/           D 的走线算法、曲线检查与暴露线长
  service/
    ports.py           存储、识别、生成及资产操作的最小能力接口
    scenes.py          场景编辑、规划、应用与版本检查
    generation.py      生成任务、恢复、重试与外观结果合并
    guides.py          当前有效结果的指标汇总与指南生成
  api/                 请求响应模型、路由与 HTTP 错误映射
  db/                  SQLite 实现、事务与条件更新
  adapters/            视觉模型、Rodin HTTP 与本地资产文件实现
  bootstrap.py         创建具体依赖并注入 service，再创建路由
  main.py              暴露由装配函数创建的 FastAPI 应用
backend/tests/         领域、编排与适配器的针对性验证
```

这是包边界建议，子文件随首个用例按需建立，不先生成空目录或通用框架。JSON 字段、单位和状态仍以[数据契约](data_contract.md)为唯一来源；领域模型与 HTTP 数据转换沿用同名同义字段，不在本节另建协议。`objects/` 保留源资产，运行时 GLB 的目标位置仍按第 3 节执行。

B 在 `bootstrap.py` 的应用工厂中读取配置，创建 SQLite、HTTP 客户端、文件适配器和受限后台任务执行器，将它们注入 service，再把 service 传给 API；`main.py` 仅提供启动入口。装配函数是唯一选择具体实现和连接对象的地方，资源生命周期由 FastAPI lifespan 管理。每个应用实例装配一次，路由、算法和业务方法内不自行实例化数据库或供应商客户端。测试可在同一装配入口传入内存存储或 Fake 适配器，正式运行使用真实实现，Mock 结果仍不计为真实接入验收。

装配一次的是存储适配器或连接工厂；SQLite 连接与事务由 `db` 按工作单元创建和关闭，不把单个连接跨请求线程、后台线程共享。lifespan 负责共享 HTTP 客户端和执行器的启停，不能在每次请求重新启动任务执行器。

前端的 HTTP 请求集中在 `api/`，版本比较与结果接收集中在 `state/`；`scene/` 读取已接受的状态进行渲染和交互，不持有供应商凭证，也不自行接受异步规划结果。前端提供即时编辑反馈，后端领域规则负责最终有效性判定。

### 用例边界与可验证性

- 整理：API 校验载荷结构后交给 service；service 读取当前场景，调用领域的 ID 引用与业务校验，再调用 C 的函数。算法返回建议，不写数据库。用户接受建议时，service 校验场景 ID、输入版本及最终布局几何硬约束，再通过存储接口原子保存目标变换、递增版本并使旧规划和指南失效。`partial` 允许残留物品留在原支撑面，仍须整体几何有效；`infeasible` 保持原场景。原建议消费后只保留为历史来源，不改写其输入版本；当前指南依据基线与当前场景差异、当前布局复查生成。
- 走线与指南：service 读取已应用布局的新版本场景调用 D；保存走线结果、发布指南时再次核对场景 ID 与版本。SQLite 通过带预期版本的条件更新及事务保证检查与保存不可被并发编辑穿插；不能仅依赖前端丢弃旧响应。算法计算和外部 HTTP 请求在写事务之外执行，避免长期占用数据库写锁。未解决问题和未知基线按数据契约保留。
- 生成：service 管理内部任务与重试流程，Rodin 适配器负责提交、查询、下载及供应商错误转换，db 保存恢复查询所需标识。完成时仅对仍存在且场景 ID、物品 ID、当前 `task_id` 均匹配的物品合并外观字段，不用任务提交时的整份场景覆盖新状态；纯外观替换不递增 `scene_revision`。任务匹配与合并在存储事务内完成，重试期间保留已有可用外观。
- 错误：领域返回契约中的结果、`issues` 或领域错误；service 传播业务结果并处理 I/O 失败，API 集中映射 HTTP 响应。不可行规划仍是明确的领域结果；供应商失败进入 `generation.error`，不伪装成几何错误。具体 HTTP 状态和实际启动命令待实现后记录。
- 验证：C、D 在无 Web 服务、无数据库、无凭证的环境中运行共同场景和几何失败案例；B 用 Fake 能力实现验证过期结果、并发编辑、重试和任务替换，再用临时 SQLite 验证事务与条件更新，用 API 检查结构拒绝和错误映射。真实视觉与 Rodin 接入另按任务清单保留证据。

规则可用数据对象和纯函数表达，有明确状态不变量时再放入对象方法；不强制把所有算法改写成类。首版只建立能隔离框架、数据库和供应商的必要边界，由 A、B、C、D 按原有职责实现。

### 生成提交与恢复边界

先持久化内部任务及“尚未提交”的恢复信息，再调用供应商；提交前记录“正在提交”，拿到供应商标识后立即保存。重启后，确定尚未提交的任务可以继续，已有供应商标识的任务只恢复查询或下载。任务提交超时，或进程在供应商受理后、标识落库前退出时，必须视为“提交结果未知”，不能当成普通查询超时自动重提。

供应商确实支持幂等提交或按客户端标识查询时，适配器使用内部任务标识恢复；支持情况须真实核验。无法确认时，以既有 `failed` 状态及 `generation.error` 说明“提交结果未知，可能已受理”，保留简化模型或旧资产，提示用户核对后再显式重试；该操作可能新建付费任务，不能宣称已保证供应商端恰好提交一次。上述恢复信息是后端持久化细节，不新增前端任务状态枚举。缓存键至少包含图片内容、裁剪区域、供应商版本及生成参数，不能只按图片 URL 命中。

## 3. 空间与资产处理

所有模块使用数据契约规定的米制、右手 Y-up 坐标、底面中心锚点与绕 Y 轴的弧度旋转。接口保存局部坐标，由物品变换计算世界坐标。

显示模型与碰撞模型分离。简化碰撞体和用户确认的尺寸是规划依据；Rodin 完成后仅替换外观，不重置已有位置或重新推测尺寸。统一字段和结果示例只在数据契约中维护。

先用参数化几何开发。现有 `.blend` 与 `.obj` 需检查尺寸、轴向、锚点后导出 GLB，并使桌体网格与支撑面、碰撞体、穿线孔及背板通道一致。最终验收目标路径为 `models/dorm_desk_assembled.glb`，当前尚未生成；该文件只包含桌体固定结构，可移动物品通过独立 GLB 导入，避免重复加载。至少提供 1 个独立单品 GLB，目标为 1–2 个，其中至少 1 件来自真实 Rodin 任务。

前端提供 `importModel(url, name, position)` 导入入口，内部创建稳定 UUID 并注册拖拽，后端校验后保留该 ID；模型替换仍使用已有物品 ID。三参仅足以创建导入草稿：模型包围盒可作为 `estimated` 尺寸候选，仍需补齐类别、规划尺寸、允许区域、碰撞体等必需字段并确认尺寸后才能整理；走线另须确认所引用的接口。不能把显示网格直接当碰撞模型。提供“智能收纳”“智能布线”和双策略切换，以及两类结果的解析入口；先用本地 Mock 验证接口，再以真实结果完成最终验收。

## 4. 整理算法

把桌面、上层四格书架与右侧抽屉内底面视为独立支撑面，物品用底部矩形与高度表示。抽屉使用固定可访问状态的收纳区域，检查内壁和净高，暂不做开合动画。识别清单区分常用外设与待收纳杂物，经用户确认后，键盘、鼠标、数位板保留主桌面中央，课本、水杯、收纳盒等分配至书架或抽屉，再按尺寸与使用频率贪心摆放，尝试 0° 和 90°。

几何硬约束：不重叠、不越界、具备支撑、层高足够、不占用保留区、固定物品不被自动移动；固定墙面设备按墙面规则检查。允许区域和自动朝向约束推荐目标，无处收纳的物品可以留在几何合法的原支撑面并标记未安放。评分优先保留连续操作空间，再考虑拿取和搬动成本。不承诺全局最优。

首版只检查一个贪心布局；无处摆放的物品保留原位并返回原因，最终结果必须包含它们参与碰撞检查。若残留物品与推荐位置冲突，回退相应移动，不将有冲突的布局提交为有效方案。多候选联合优化作为后续任务。

归位动画采用位置插值，只表达前后状态；执行指南另行说明真实搬动顺序。

## 5. 走线算法

具体输入校验、A* 与双策略图搜索、曲线生成、线缆体积复查、多线汇聚和 `cable_routing.json` 示例见[走线算法规划](routing_algorithm_plan.md)。

用户可在任意物品表面取点，确认设备接口类型、连接对象、线长、线径和弯曲半径；世界坐标转换为所属物品的局部接口坐标。支持粗线与细线预设以及 4/6/8 位插排选择，各插孔独立分配，支持多线缆向插排汇聚；校验连接类型及孔位占用，不按外观猜测隐藏连接。墙插与网口默认离地 0.30m，可在墙面内调整，必须支持沿 Y 轴调节。

在配置好的允许走线网络中，以接口、桌沿、穿线孔、背板后通道、桌下和立柱固定点为节点，用 A* 或 Dijkstra 求路，优先沿墙和固定通道收拢。禁入区和净空不足的边直接排除；总长度必须计入接头与移动余量。多线缆可共用允许通道，但仍需检查通道净空与线缆间占用，不能用重叠中心线代替有效汇聚。

先求路径，再做三维样条平滑，最后检查碰撞、线径净空、长度和最小弯曲半径。输出包含已验证的三次 Bézier 样条控制点与同一曲线的采样点，具体字段只在数据契约维护。没有通过复查的曲线不能标记为有效。尝试路径数量必须有上限，失败时说明线长不足、无可行路径或其他具体原因；不能把尖角折线直接当作可执行线缆。

首版必须支持穿线孔和背板后两种策略，在同一可行测试端点上分别生成符合策略的不同路径。穿线孔路径必须经实际开孔下行，背板后路径必须绕至背板后通道下行；策略对应通道未配置时返回 `unsupported_mode`，不得悄悄切换策略。附件“任意两点成功”按物理可行性验收：任意合法表面点均可提交，可行条件下生成有效样条，遮挡、线长不足或无通道时返回明确失败。

移动物品、接口、插排或障碍物后，旧路径和指南失效；前后端接收或保存结果前均校验场景版本，首版对全部请求线缆重新验证，避免复用未复查的旧线。重新规划不自动反复重排布局，失败时请用户调整相关条件。

## 6. 指标与执行指南

原始状态由用户确认后保存为不可变快照；当前场景与规划结果使用版本标识。指南由基线到当前场景的变化、当前布局复查、连接关系和当前版本路径生成，不依赖已消费布局建议继续有效。内容包括物品移动、穿线孔和固定点、线长与未解决事项；变更场景或重建基线后需重新生成。

比较指标使用同一套规则：桌面连续可用面积、桌面暴露线长、未解决冲突数。面积使用扣除占用和保留区后的固定分辨率网格，取最大四邻接连通分量面积；前后采用相同网格精度并在报告中注明。暴露线长按路径位于 `exposure_zones` 并集内的弧长求和。原始线缆位置尚未录入时，原始暴露线长标记为未知，不推造改进百分比。

C 负责连续可用面积与布局问题，D 负责暴露线长与走线问题；B 调用两者的评估函数，按[数据契约第 6 节](data_contract.md#6-比较指标与指南数据)汇总独立比较载荷并生成指南，A 展示。任一原始路径未知或当前线缆失败时，对应完整总长为未知，不以成功线缆小计制造改进；物品/连接集合变化后的不可比项同样明确说明。

不实现独立的多轮 Agent 调度；用户偏好先用结构化选项输入。后续再引入自然语言偏好提取，并由确定性算法验证最终结果。

### 超时处理顺序

1. 开发中优先保留简化几何，暂缓材质与视觉美化；最终桌体 GLB 加载和独立单品 GLB 仍需验收。
2. 只生成 1 件真实 Rodin 资产，其他物品使用简化模型或已标注缓存。
3. 先用穿线孔与 4 位插排联调，再补齐背板后策略、6/8 位插排和抽屉区域；缺少任何一项均记为附件验收未完成。
4. 使用简单状态切换和位置插值，不增加视觉特效；手机保证上传、预览和查看。
5. 识别失败时允许手动清单完成演示，同时如实记录识别未达标；服务凭证或配额阻塞真实生成时明确记录，不以缓存替代真实接入验收。

上述降级不能省略几何约束、失败反馈或结果版本检查，也不能免除附件验收项。核心能力未通过验收时必须报告未完成，不能将缩减演示等同完整交付。

## 8. 后续扩展

首版完成后再安排多候选布局与走线协同、抽屉开合、自由堆叠、完整移动端编辑、AR 与打印。

打印配件使用参数化 CAD 控制夹口、公差、壁厚和受力结构；Rodin 仅参与外观探索。STL 是网格模型，经过切片检查和实际试装后才能标为适配，不承诺固定打印时间。
