# DormTopology 3D 研发任务与验收

本文追踪待实现任务，当前复选框均未验收。范围、工期与职责以[实施方案](implementation_roadmap.md)为准，模块数据以[数据契约](data_contract.md)为准，交互见[用户体验设计](ux_design.md)。

2026-10-16 按用户要求合并所提供的附件 `tasks.md`，保留原有几何、状态与真实接入验收。第 8 节逐项对应附件；Mock 通过只代表接口阶段完成，最终仍需真实联调。附件中的“任意两点成功”按可行条件验收，不可行输入必须明确失败；样条控制点与已验证采样点共同输出，具体协议仅在数据契约维护。

团队共 4 人：A 负责前端，B 负责后端，C 独立负责物品布局算法，D 独立负责走线算法。第 4、5 节为两个独立开发任务，各自交付算法函数、结果样例和验收记录；两人先用共同场景并行开发，实际流程按已应用布局的当前版本进行走线。

## 1. 共同前置任务（H0–H4）

负责人：A、B、C、D 共同确认；数据契约变更由四人同步。

- [ ] 确认场景单位、坐标轴、原点、底面中心锚点和旋转约定。
- [ ] 按数据契约制作场景、整理结果和走线结果样例，验证字段、ID 引用与错误状态。
- [ ] 建立一个演示场景：8 件物品、3 根线、桌面中央区域、上层四格书架与右侧抽屉收纳区域、碰撞体和禁入区。
- [ ] 配置真实存在的穿线孔及背板后通道，准备同一对可行端点的两种不同路径案例；缺少通道时明确失败，不能作为双策略验收通过。
- [ ] 配置 4/6/8 位插排的尺寸、独立插孔与总线接口，以及默认离地 0.30m 的墙面网口和双孔插座面板。
- [ ] 明确原始快照、当前场景和规划结果的版本；拒绝将旧版本结果覆盖到新场景。
- [ ] 确认 C 主责的共享坐标变换、物品碰撞几何及容差接口，D 复用并核验；C、D 各自提供结果样例，B 分别接入两个算法函数。

- [ ] 切换前后状态不修改原始快照；缓存资产与实时生成资产有可见区别。

## 4. 成员 C：物品布局算法

独立任务负责人：C。输入为数据契约中的已确认当前场景，输出为 `packing_result.json`、连续可用面积和布局问题。依赖共同场景、区域与物品尺寸；先用简化碰撞体开发，不等待 Rodin 或 D 的走线实现。

- [ ] 以 Python 模块交付布局算法与共享几何，提供可供 B 的 FastAPI 后端直接调用的函数接口。
- [ ] 主责共享坐标变换、旋转后物品碰撞体与几何容差，提供最小函数接口及旋转/碰撞样例给 D 复用；D 的线缆体积和曲率校验由 D 负责。
- [ ] 实现桌面、上层四格书架和右侧抽屉多平面摆放，限制为 0°/90° 朝向，不做自由堆叠或抽屉开合；检查抽屉内壁与净高。
- [ ] 键盘、鼠标、数位板保留在主桌面中央区域，课本、水杯、收纳盒等杂物分配至用户确认的书架格或抽屉区域。
- [ ] 校验边界、碰撞、支撑、层高、固定物品与操作保留区域。
- [ ] 按使用频率、连续操作面积和搬动成本等目标贪心摆放，首版只生成一个布局。
- [ ] 无处摆放的物品保留原位并返回原因；不通过删除物品制造成功结果。
- [ ] 按数据契约输出整理 JSON，覆盖全部物品及名称、模型路径、当前/目标坐标和失败原因；结果携带输入场景 ID 与版本，交给 A、B 应用。
- [ ] 物品、区域或障碍物变化后重新验证布局；只输出建议，不自行覆盖场景或改动线缆连接。
- [ ] 用同一网格精度计算整理前后的连续可用面积，提供布局 `issues` 给 B 汇总；不负责暴露线长指标。
- [ ] 向 A、B 提供正常、部分成功、不可行及版本变化案例，记录算法运行与验收结果，并配合 D 核对应用后场景。

验收：

- [ ] 正常场景整理后，已放置物品满足全部硬约束；固定物品不移动。
- [ ] 常用外设保留桌面中央，杂物目标坐标位于四格书架或右侧抽屉的内部容积内，不重叠、不穿模；准备书架与抽屉各至少一个落位案例。
- [ ] 空间不足时返回部分成功或不可行，未安放物品仍存在于场景中并参与最终碰撞检查；不可行结果保持输入变换。
- [ ] 覆盖旋转物品、越界、缺少支撑、净高不足及保留区冲突案例；共享几何与 D 使用相同坐标和容差。
- [ ] `packing_result.json` 符合数据契约，前端能解析、渲染和导出；输入版本与结果一致，有效布局应用后形成供 D 使用的新版本场景。
- [ ] 前后面积采用相同网格精度，布局问题可追溯且不靠删除物品消除冲突；完成该任务无需等待走线任务通过。

## 5. 成员 D：走线算法

独立任务负责人：D。输入为当前场景、已确认接口与线缆，输出为 `cable_routing.json`、暴露线长和走线问题。依赖共同场景、通道配置及与 C 约定的共享几何接口；从共同场景独立开发，不等待 C 的布局算法完成或 Rodin 外观资产。实际联调输入必须是 A、B 应用有效布局后的当前场景。

- [ ] 以 Python 模块交付走线算法，复用 C 的共享几何，提供可供 B 的 FastAPI 后端直接调用的函数接口。
- [ ] 建立接口、桌沿、穿线孔、背板后通道、线槽与立柱固定点构成的可走线网络，优先贴墙收拢；实现穿线孔与背板后两种策略。
- [ ] 校验 A 由合法表面点写入的局部接口坐标，复用共享变换计算真实世界端点；粗线与细线使用不同线径、弯曲半径预设，实际按确认数值校验。
- [ ] 按接口类型和插孔占用情况检查连接；用 A* 或 Dijkstra 搜索路径。
- [ ] 支持 4/6/8 位插排独立插孔分配与多线缆汇聚，检查共享通道净空与线缆间占用，不能将重叠中心线视为有效汇聚。
- [ ] 校验线径净空、线长、余量、弯曲半径与禁入区；失败时提示用户调整，不自动循环重排。
- [ ] 生成三维样条，输出已验证的控制点与同一曲线采样点；平滑后复查碰撞、长度和弯曲条件，失败时尝试其他路径或返回失败；不能将尖角折线作为可执行线缆。
- [ ] 按数据契约输出走线 JSON，包含控制点、采样点、粗细、线径、策略和有效性，覆盖全部请求线缆；结果携带输入场景 ID 与版本，失败路径为空。
- [ ] 物品、接口、插排或障碍物变化后，重新验证受影响的走线；不修改物品布局，不自动循环调用 C 重新摆放。
- [ ] 用同一规则计算整理前后的桌面暴露线长，提供走线 `issues` 给 B 汇总；缺少原始线缆路径时将基线标为未知。
- [ ] 向 A、B 提供双策略成功、失败及版本变化案例，记录路径尝试上限、运行与验收结果，并用 C 实际布局应用后的场景验证重算。

验收：

- [ ] 同一对可行测试端点按参数分别生成穿线孔与背板后两条不同有效样条；前者通过实际开孔，后者绕至背板后下行，均通过几何复查。
- [ ] 可提交任意合法表面点，在可行条件下生成连接真实端点的三维样条；不可行条件返回明确原因，不保证任意两点都必有路径。
- [ ] 粗线/细线均输出正确的 `thickness` 与不同线径参数，实际弯曲半径满足确认值；4/6/8 位插排均通过孔位分配，多线汇聚不冲突。
- [ ] 覆盖线长不足、接口遮挡、通道过窄、插孔占用和不兼容接口案例，均不输出有效路径。
- [ ] 输出路径包含真实端点，平滑后仍满足约束；移动或旋转设备后接口世界坐标正确更新。
- [ ] 超出走线路径尝试数量上限时终止并说明失败，不无限重试。
- [ ] `cable_routing.json` 符合数据契约，前端能解析、渲染和导出；控制点与采样点描述同一已验证曲线，失败结果不携带有效路径。
- [ ] 先用共同场景完成独立走线验收，再在已应用布局的新版本场景中重算，旧结果不覆盖新场景且不改动物品位置。
- [ ] 暴露线长按相同区域与弧长规则计算，原始路径未知时不生成改进比例；走线问题可单独追溯给 B 汇总。
