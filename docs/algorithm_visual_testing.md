# 算法可视化验证

算法验证工作台位于前端 `/algorithm-lab`，也可从项目首页的「算法验证」进入。它直接读取 Python 领域算法导出的契约 JSON，不调用前端 Mock 或规则式规划器。产品工作台的 FastAPI、持久化及真实算法调用仍待联调。

## 运行

需要 Python 3.11+、Node.js 20+ 和支持 WebGL 的浏览器。领域算法和样例生成器只依赖 Python 标准库。

```sh
# 仓库根目录：重新运行真实算法，生成版本受控的静态样例
python3 -B -m backend.examples.algorithm_fixtures

cd frontend
npm ci
npm run dev -- --host 127.0.0.1
# http://127.0.0.1:5173/algorithm-lab
```

`frontend/public/algorithm-fixtures/manifest.json` 列出 13 组输入和结果。生成器先验证实际结果状态，再写入文件；重复生成不写入时间戳或耗时。查看器不会在浏览器中执行 Python，修改输入后须重新运行算法或导入新的结果。

| 场景 | 真实结果与用途 |
| --- | --- |
| `packing-success` | 8 件待整理物品全部落位；基础设备另计，面积 0.6344 → 0.7390 m² |
| `packing-partial` | 收纳盒无法进入目标区域，保留原位并继续显示；面积 0.6344 → 0.7134 m² |
| `packing-infeasible` | 固定墙插越界，全部保持输入变换，不产生应用场景 |
| `packing-revision-2` | 输入和整理结果为 v2，模拟应用后的场景及走线结果为 v3 |
| `routing-slot` | 在分割桌板的实际开孔通道中下行，成功输出已验证采样点 |
| `routing-backboard` | 在背板后下行，成功输出已验证采样点 |
| `routing-length-exceeded` | 线长不足，失败结果的路径为空、长度为 null |
| `routing-endpoint-blocked` | 接口引出段受阻，失败结果的路径为空、长度为 null |
| `routing-supported-edge` | 沿桌面后沿、真实孔边和柜侧扎带布线；最大无支撑跨距上界约 0.1631m |
| `routing-underdesk-ties` | 桌面下方 13mm，使用 6 处实际挂载扎带；跨距上界约 0.1650m |
| `routing-underdesk-tray` | 同一桌下通道使用连续机械集线托盘；跨距上界约 0.0125m |
| `routing-unsupported-span` | 同一桌下通道没有固定件，返回 `unsupported_span`，不绘制有效连接 |
| `routing-underdesk-composite` | 三根线先在扎带支撑下独立规划，再输出共同收入候选集线槽的建议；原路径和支撑证据保留 |

走线案例均为独立几何诊断；最初两个成功案例终点位置不同，桌下 `backboard` 案例用于检查固定条件，不计为同端点双策略或三线汇聚验收。新增支撑案例使用 0.23m 跨距上限，仅为演示参数。8 物品共同场景的走线失败仍如实显示，不用诊断场景替代其验收。

## 查看与导入

工作台采用契约的米制、右手 Y-up、底面中心锚点和绕 Y 轴旋转。盒状物品、固定障碍和支撑区域从输入几何生成，不需要预先准备 GLB；精细外观和真实资产仍按原任务验收。可切换整理前后、收纳区域、碰撞体、保留区域、走线网络和有效线缆，提供透视、俯视、正视、桌底视图及复位；线缆按 ID 保持颜色。点击物品查看 ID、尺寸、位置、朝向和目标区域。

「固定与支撑」图层按障碍安装面、切向范围和离面量绘制承托面、扎带和集线托盘，可选择查看 ID 与安装参数。线缆详情区分支撑已复查/未评估，并显示跨距上限、算法给出的最大跨距上界及实际使用的支撑 ID。桌底附近没有固定件不能视为已支撑；原 8 个场景未开启支撑策略，均明确显示未评估。支撑字段见[数据契约](data_contract.md#24-走线支撑与固定件)，当前不模拟下垂、张力或承载力。

「集线槽建议」采用独立图层，展示可选安装范围，组合详情显示成员、保守共用长度和占用/可用宽度。候选不会加入已安装支撑，不会改动逐线曲线，也不将失败路线标为有效。当前只展示配置候选内可收束的共享段；接受、安装确认、版本保存与指南联调尚未接入。

线缆按算法提供的 `path_points` 绘制折线，不重新拟合样条。当前线条使用屏幕宽度增强辨识度，不作为实际线径测量工具；算法的线径、净空和曲线检查仍由 Python 负责。失败线缆不绘制连接。暴露长度直接读取算法指标，未知值不当作零；面积只显示随内置样例生成的真实计算值，外部导入未提供该指标时显示未知。

「导入 JSON」一次选择以下文件，文件名须完全一致：

- `scene.json`：必需，规划输入。
- `packing_result.json`：可选，与输入场景 ID、版本匹配。
- `applied_scene.json`：可选，成功或部分成功布局的模拟应用场景；版本为输入加一，只允许修改物品位姿和版本。
- `cable_routing.json`：可选，有应用场景时匹配应用版本，否则匹配输入版本。

只有整理建议而没有应用场景时，整理后显示建议预览，不伪造版本递增。输入版本的走线只能在原场景上显示，不叠加到已移动的建议物品上。内置样例的版本递增是离线模拟，不代表后端原子应用已经实现。

解析器校验结构、有限数值、唯一 ID、引用、完整结果覆盖、固定或残留物品保留、版本以及真实接口端点。失败路径含非空几何、过期结果、应用时篡改尺寸/接口等输入会被拒绝；错误保留已加载数据。JSON 结构检查不替代领域几何复查，不把用户导入的 `valid` 标签当作新的算法验收。

查看器最多接受 4 个文件，每个 8 MB；资源预算包括 256 件物品、512 个接口、128 个区域、每类 256 个体积、512 个图节点、1024 条边、256 处线缆支撑、256 个候选集线槽、512 个槽优化结果、256 根线、总计 200,000 个路径点和 20,000 段曲线。几何坐标和尺寸绝对值上限为 1,000,000m。这些是查看器资源限制，不修改领域算法的数据契约。

## 浏览器检查

```sh
cd frontend
npx playwright install chromium
npm run test:e2e
npm run test:e2e:ui
npm run test:e2e:report
```

配置会自动在 `127.0.0.1:4174` 启动 Vite；端口被占用时停止冲突进程，或通过 `PLAYWRIGHT_BASE_URL` 指向已经运行的本地服务。测试覆盖桌面 Chromium 和模拟 Pixel 7 的手机 Chromium，输出位于被 Git 忽略的 `test-results/` 和 `playwright-report/`。

检查包含 13 类实际结果、Canvas 非空像素、相机轨道交互、前后切换、物品/支撑/候选选择、图层开关、支撑证据及安装约束、集线槽分组、JSON 导出、版本拒绝、错误导入保留状态及应用场景一致性。每个场景保留截图供人工复核；当前未配置跨平台逐像素基线比较。手机项目是浏览器视口和触摸模拟，不能替代真实手机或完整产品流程验收。

## 验证记录（2026-10-17）

本机 Node 22.23.1 下，`npm run build`（含 TypeScript 检查）通过；`npm run test:e2e` 同次运行 68/68 通过，耗时约 1.5 分钟，桌面及模拟 Pixel 7 各 34 项。已人工查看布局、穿线孔、背板后、支撑及三线组合的桌面/手机截图，无空白场景或控件重叠；Canvas 像素、桌底相机、线色稳定性及候选开关检查通过。报告通过 `npm run test:e2e:report` 打开。构建仍提示 Three.js 产物块超过 500 kB，未在本轮改动应用打包策略。

样例生成器的 Ruff 检查及重复生成一致性通过，96 项领域测试和 1 项兼容测试通过。新增回归覆盖连续曲线跨距、平滑脱离支撑、安装范围、扎带间距、多线侧移离开窄托盘，以及可选集线槽的连续共享段、宽度、间距、预算和安装前后语义；未安装候选不能补救失败路线。关联文档的本地文件链接和 `git diff --check` 通过。独立对话预览使用相同 13 组实际样例的嵌入数据，已检查桌面、手机、320px 深色主题及状态恢复；它不发起算法请求，不替代仓库中的浏览器回归。
