# 物品布局算法实现与交接

实现入口为 `backend.app.domain.packing`，适用于成员 C 的算法交付。空间、字段、状态和面积口径仍以[数据契约](data_contract.md)为准；本页记录实现选择、运行方式及算法级证据，不替代[研发任务与验收](project_tasks.md#4-成员-c物品布局算法)。

## 调用与运行

需要 Python 3.11 或更高版本；领域模块与样例只使用标准库，无安装步骤、环境变量、Web 服务或供应商凭证。以下命令均在仓库根目录运行。

```python
from backend.app.domain.packing import (
    PackingInputError,
    measure_free_area,
    plan_packing,
    validate_layout,
)

result = plan_packing(scene)
check = validate_layout(scene)
area_m2 = measure_free_area(scene)
```

输入和输出均为契约同名字段的字典；`domain/models.py` 提供 `Scene`、`PackingResult`、`LayoutCheck` 和 `Issue` 类型提示。函数不读取或写入文件、不修改输入，不改变场景版本、外观、接口或连接关系。

`plan_packing` 要求已确认基线及全部物品尺寸。`validate_layout` 和 `measure_free_area` 可以评估尚未确认基线、尺寸的编辑草稿，但仍要求完整且结构合法的载荷；它们的检查不代表用户已确认草稿。接口可以在整理后确认，未确认的接口不会阻止整理。

电脑主机属于“先平移、后旋转”的特殊摆放规则：候选评分先按原始朝向分组，在原朝向存在合法位置时优先选择平移后的候选；仅当原朝向没有合法候选时才比较其它允许朝向。这样可避免为躲避座位区而原地旋转主机，保留主机正面朝向用户。

三个入口均复用 `backend/app/domain/rules.py`，先检查结构、有限数值、全局 ID 唯一性和引用；走线入口也复用同一结构规则，再检查所连接口的确认状态。缺字段、不能转换为有限浮点数的极大整数，以及因浮点精度坍缩或溢出的物品世界碰撞体，在规划前拒绝。布局无效输入抛出 `PackingInputError`，带有 `code="invalid_input"` 和 `field`；HTTP 映射由 B 实现。有效结构中的几何问题通过契约 `issues` 返回，不能把无法支撑的场景描述为输入格式错误。

运行测试和生成可供 A/B 使用的四类输入、结果 JSON：

```sh
python3 -B -m unittest discover -s backend/tests -v
python3 -B -m unittest discover -s algorithm/cable_routing/tests -v
ruff check backend algorithm
python3 -B -m backend.examples.packing_demo --output-dir /tmp/dormtopology-packing-examples
```

最后一条命令生成 `success`、`partial`、`infeasible`、`revision_2` 各自的 `*_scene.json` 和 `*_packing_result.json`，输出文件名不同但内容均直接遵循场景与整理结果契约。样例生成器在 `backend/examples/packing_demo.py`；领域算法不依赖此生成器，也不通过磁盘通信。

需要三维查看时，在仓库根目录运行 `python3 -B -m backend.examples.algorithm_fixtures`，随后进入前端 `/algorithm-lab`。工作台直接解析真实算法结果，除上述基础布局外，还包含综合设备布局、支撑与集线槽走线诊断；完整样例清单、生成方式、版本规则和 Playwright 检查见[算法可视化验证](algorithm_visual_testing.md)。

## 摆放与复查

1. 先按显式 `placement_priority` 降序，再根据允许区域数量、底面积、使用频率和物品 ID 确定稳定的贪心顺序。缺省优先级为 0；固定物品从始至终保留原变换。高优先级不免除几何约束，也不替代设备的目标区域。
2. 读取 `allowed_region_ids`，依次尝试允许的 0°/90° 朝向。类别对应的桌面中央、四格书架和抽屉由用户确认的区域引用决定，不靠物品名称推测目标，也不擅自扩大允许区域。
3. 候选位置来自区域边界、区域中心、原位投影及物品/障碍物边缘；物品边缘候选加上配置的最小净距。先复查完整支撑、边界、净高、禁入区、物品碰撞和净距，再对每个区域、每个朝向最多 128 个合法候选计算连续面积。合法且已满足目标的原变换也作为候选，可保留任意手动朝向。
4. 若提供 `preferred_region_ids`，先选择完整落在任一偏好区域内的几何可行候选；偏好组不可行时允许回退到其他 `allowed_region_ids`。同组区域不按数组顺序排序。再优先减少接口引出段被其他物品遮挡的数量，随后最大化已布置场景的桌面连续可用面积，最后考虑按使用频率加权的取用距离、移动距离和旋转成本。未提供接口的场景不增加接口评分。取用点使用主桌面前缘中点；这是原型启发式，不代表真实人体工学结论。
5. 无目标可用时保留输入变换。此前移动若与残留物品冲突，迭代回退相应移动；回退到已满足目标的合法原位时恢复 `unchanged`。
6. 对全部目标与残留物品复查。整体几何合法才输出 `success` 或 `partial`；否则全部恢复输入变换，返回 `infeasible` 和问题，不输出可应用的部分移动。

算法只生成一个确定性贪心方案，不做全局最优搜索、自由堆叠、抽屉开合或搬运路径规划。候选集合和贪心顺序可能错过可行方案；`infeasible` 表示本算法未找到完整有效布局，不是数学上的无解证明。未安放物品通过 `no_space` 和具体文字说明原因；实际相交另有 `collision` 问题。

物品最小净距由场景 `constraints.min_item_gap_m` 指定，历史缺省为 0，产品整理默认 20mm。候选、合法原位、残留物品回滚、最终复查及后端原子应用使用同一规则；前端还独立拒绝过密的伪造结果，在接受请求发送前与历史候选恢复时复查，拒绝不写入项目或撤销历史。默认约束纳入输入签名，使旧约束生成的内存方案在发送请求前失效。按真实凸部件的 Y 正重叠与 XZ 投影最短欧氏距离判定，不用整体包围盒填实凹口，不跨搁板层互相阻挡。倾斜部件投影是保守近似，具体边界见[数据契约](data_contract.md#22-区域与碰撞几何)。明确插接的适配器与所属插排只豁免间距，不能豁免实体碰撞。间距不足单独报告 `item_spacing`；固定或未安放物品不满足时，不能通过忽略它们让结果可应用。规则只设最小值，连续可用面积仍决定满足净距后的紧凑布局，不鼓励摊散物品。

产品整理同时保留穿线孔上方的出线空间，避免满足物品间距的新位置盖住孔口；走线请求清空该布局专用保留区，让线缆仍可通过真实孔洞。该约束不扩大孔洞或豁免设备碰撞。

接口可达性是软偏好：对已定义接口复用局部/世界变换，沿真实出射方向检查 25mm 引出段及 5mm 保守净空，双向检查候选物品的接口是否被已摆物品遮挡，以及候选物品是否挡住已摆物品的接口。检查使用真实 OBB/凸体碰撞与 AABB 粗筛，不添加虚构实体或放宽既有几何约束。接口未确认时仍可参与整理启发式，但不能因此报告接线已确认或走线可行；无法兼顾时仍保留合法布局，最终由走线算法如实返回 `endpoint_blocked` 等原因。布局的 `success` 不代表完整线路有解。

物品是否适合落地由上游按属性生成的允许区域约束决定，领域算法不根据名字推测。产品真实整理与本地演示共用落地资格规则，具体默认值见[数据契约](data_contract.md#21-物品)。`preferred_region_ids` 是偏好而非许可，不可通过偏好字段扩大允许区域，也不能为腾空桌面绕过禁止落地的限制。

产品后端规划的场景适配由 `frontend/src/api/core/packingWire.ts` 提交设备用途约束：显示器以键鼠区中线后的中央主视位为首选，优先级 100；打印机仅允许桌面侧部设备区，优先级 90；二者生成的新位置均面向用户。中央主视位不可行时，显示器可回退到其他合法桌面位置并显示原因；打印机侧区不足时保留原位并反馈未安放，不借用显示器背后的位置制造成功。结果还会复查最终显示器与打印机的横向列是否重叠。这些用途约束不能代替或放宽领域几何检查，固定和锁定物品保持原位。

产品中的 `powerAdapter` 按工作设备约束在桌面非保留区域，与笔记本和台灯使用相同的桌面许可，不自动收进没有出线通道的静态抽屉。该许可由前端适配器提交；领域算法仍只遵循 `allowed_region_ids`，不根据物品名称擅自扩大或收紧区域。直插插排的固定适配器继续遵循原有插接规则。

`validate_layout` 的 `geometry_valid` 只代表硬约束。杂物留在合法桌面、但未进入允许的收纳区域时，`geometry_valid` 可以为真，同时 `issues` 包含未完成收纳的问题。无论固定与否，普通物品都必须落在声明的完整支撑区域；墙面设备按墙面规则检查，固定直插适配器按[插接规则](data_contract.md#26-插排上的直插适配器)复查支撑与端口接触。该例外不允许其他物品自由堆叠。区域是普通物品的支撑面事实来源，实际开孔和缺口必须从区域中排除，不能依赖外观模型弥补错误配置。

## 共享几何与面积

`backend/app/domain/geometry/` 提供局部/世界点与方向的双向变换、旋转 box 的世界 AABB、X/Z 矩形 SAT、物品/物品及物品/障碍物碰撞、支撑区域查询。物品碰撞使用绕 Y 轴的 OBB 投影与高度区间，支持任意手动朝向，不用 AABB 近似替代布局碰撞。

支撑底面高度匹配允许 0.001m 容差；区域水平边界、物品高度和世界顶面净高只忽略 1e-10m 的浮点噪声，不能以支撑容差扩大可用容积。相交判断同样只忽略 1e-10m 噪声，接触面可作为支撑，不算体积碰撞。无法形成有限、非退化世界碰撞体的尺寸或变换作为无效输入拒绝，不让退化矩形进入 SAT 碰撞计算。

数值样例：底面中心在 `[0.5, 0.77, 0.3]`、绕 Y 轴旋转 π/2 的物品，局部点 `[0.1, 0.05, 0]` 转为 `[0.5, 0.82, 0.2]`；局部方向 `[1, 0, 0]` 转为 `[0, 0, -1]`。逆变换返回原局部值。

D 的走线核心现位于 `backend/app/domain/routing/`，曲线与线缆体积验证由 D 维护，`resolve_port_world` 复用上述共享变换。后端规范入口为 `backend.app.domain.routing.plan_routing`，`plan_routes` 是同一函数的兼容名称；旧 `algorithm/cable_routing/` 仅重新导出领域实现，不包含业务算法，领域层不反向依赖旧包。

面积实现位于 `packing/area.py`，按契约的 0.01m 网格，将旋转底部投影和桌面保留区的占用取并集，再用整数位集合计算最大四邻接连通分量。网格限于桌面高度区域的并集，L 形包络中的空区不计面积，重叠用途区域不重复计数；边界以厘米网格近似，格线接触不占用。不累加书架/抽屉面积或悬空物品投影。B 应分别对不可变基线与当前场景调用本函数，并按契约决定是否可比，不把本次规划输入当成原始快照。

产品固定家具 `dormdesk-v1` 的共享资产变换、真实支撑面、75 个保守障碍与开孔由前端适配器导出，后端不依赖 Three.js 或 GLB 加载；见[桌体接入](../frontend/docs/desk-model.md)。候选重叠区域产生的相同姿态会去重，固定障碍先做 AABB 粗筛再做原有精确几何复查，不放宽碰撞约束。

当前原型的面积计算最多支持 1,000,000 个网格单元；这是计算资源上限，不是新的物理尺寸规范。布局规划与面积入口在分配前拒绝无法表示或超限的桌面网格，返回 `PackingInputError`（`field="desk"`）；桌外物品与保留区投影先裁剪至有效网格范围再换算，避免有限坐标在除以格宽后溢出。
