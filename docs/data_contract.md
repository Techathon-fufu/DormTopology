# DormTopology 3D 数据契约 v1

本文是空间和模块数据的唯一约定，属于待实现协议。首版范围见[实施方案](implementation_roadmap.md)。`scene.json`、`packing_result.json`、`cable_routing.json` 表示数据载荷名称，不要求算法通过磁盘文件通信；应用接口路径由后端实现时记录。

## 1. 坐标、单位与资产

| 项目 | 约定 |
| --- | --- |
| 世界坐标 | 右手系，Y 向上，X 向桌面右侧，Z 从桌后朝使用者 |
| 原点 | 桌面左后角在地面上的投影；桌面区域为 X ≥ 0、Z ≥ 0 |
| 长度与位置 | 统一用米，面积用平方米；界面可转换为厘米或毫米 |
| 物品尺寸 | `size_m: [width, height, depth]`，分别对应未旋转的局部 X/Y/Z |
| 物品位置 | `position` 为底面中心的世界坐标，非模型包围盒中心 |
| 物品朝向 | `rotation_y_rad`，按右手规则绕 Y 轴旋转，单位弧度；自动摆放从物品声明的有限候选集合选择，默认 0 或 π/2 |
| 接口位置 | `local_position` 相对所属物品的底面中心，`local_direction` 为朝外单位向量 |
| 接口变换 | 世界位置为 `position + R_y(rotation_y_rad) × local_position`，方向仅乘旋转矩阵 |
| 墙面位置 | 后墙为配置的固定 Z 平面；墙插和网口沿 X/Y 调整，不能脱离墙面 |

演示配置 ID 为 `demo_desk_v1`：桌宽 1.45m、净深 0.60m、桌面顶高 0.77m。这些是可替换的示例参数，不是学校实测标准，也未核验现有 Blender 模型。书架尺寸、穿线孔形状和墙面位置需在首个演示场景中明确填写；不预设所有桌体都有 55cm 开孔。

演示场景必须配置上层四格书架、右侧抽屉内部收纳区域、真实穿线孔与背板后通道。墙插和网口物品底面中心的默认高度为 `position[1] = 0.30`，可在后墙平面内沿 X/Y 调整，Z 固定；该默认值同样不是实测值。桌体运行时资产仅包含固定结构；可移动物品使用独立资产。

桌体与抽屉的运行时资产路径、文件名与锚点规则见第 1.1 节。

桌体 GLB 使用同一世界原点，单品 GLB 使用底面中心锚点。Blender 源文件若为 Z-up，由导出流程转换到 glTF 的 Y-up，前端不再次旋转。资产导入时统一尺寸和锚点，保留物品变换；不能把生成网格直接当作精确碰撞体。

桌体与抽屉分属两类资产，锚点规则不同，见第 1.1 节。

物品 `size_m` 是规划尺寸；接口局部坐标使用实际米制值。编辑尺寸时必须同步更新碰撞体，并由用户重新确认接口位置，不能只缩放外观而保留不匹配的接口。

旋转矩阵采用 `R_y(θ) = [[cosθ, 0, sinθ], [0, 1, 0], [-sinθ, 0, cosθ]]`。例如局部点 `[0.1, 0, 0]` 旋转 π/2 后为 `[0, 0, -0.1]`，再叠加物品世界位置；表面取点用该矩阵的转置做逆变换。

### 1.1 桌体与抽屉的资产分离

桌体与抽屉按**两类资产**处理，锚点规则不同。本节是其唯一约定，其他章节不再重复。

| 资产类别 | 仓库路径 | 原点 | 说明 |
| --- | --- | --- | --- |
| 桌体（固定结构） | `Prefabmodel/dormdesk_parts/dormdesk_body.glb` | 家具资产共同原点 | 不含抽屉，仅柜体框架、书架、床、护栏、爬梯、立柱 |
| 抽屉（可运动结构） | `Prefabmodel/dormdesk_parts/drawer_{bottom,middle,top}.glb` | 与桌体同一世界原点 | **不走底面中心锚点**，见下 |
| 可移动物品 | `Prefabmodel/*.glb` | 底面中心锚点 | 按第 1 节，与本节无关 |

配套清单：各文件同目录的 `*.manifest.json` 记录尺寸、部件名与坐标；碰撞体见第 2.2 节，本目录的 `collision.manifest.json` 与各 `*.collision.json` 为桌体与抽屉的碰撞几何。

**加载方不得分别归一化桌体和抽屉。** 四份资产保留共同原点，统一放入父节点后应用一次共同变换；碰撞体、支撑面与接口适配必须使用同一变换。源资产的最小 X 为 0 并不表示它已经符合算法的桌面左后角原点。

当前固定家具模板 `dormdesk-v1`：资产到产品前端统一平移 `[-1, -0.02, 0.9]`，再由前端到算法/API 平移 `[0.45, 0, -0.042]`；不重复旋转或缩放。旧参数化项目保留原来的 `[desk.width/2, 0, -0.05]` 前端到 API 变换，旧快照不按新家具重新解释。前端 `RoomConfig.furnitureModel` 标记家具版本，导出的 `template_id` 使用该版本。

固定家具的 L 形支撑由两块真实桌面组成：前端主台 X `[-0.45,0.59]`、Z `[0.06,0.61]`，回台 X `[0.59,1]`、Z `[0.042,0.902]`，顶面均为 0.75m。四格书架包含左格中层，共五个支撑面（1.46m 与左格 1.668m）；三个静态抽屉内底高为 0.084/0.334/0.549m。具体边界与净高由共享家具几何导出，不能使用旧桌面书架高度或不存在的桌下横梁。桌体和抽屉使用 75 个保守部件 AABB，抽屉壳体保持拆分，内腔不填实；斜梯等 AABB 可能保守排除实际空隙。孔位须完整落在一块真实桌板内，以圆孔内接正方形切出保守通道，渲染与校验使用同一开口。

抽屉不采用单品 GLB 的底面中心锚点，而**保持与桌体同一世界原点**。原因：抽屉是场景固定结构的一部分，初始位置必须与柜体开口精确对齐；采用底面中心锚点会让同一组抽屉在不同桌体上产生位置偏差，并使装配关系依赖加载方另行换算。

三个抽屉的**初始位置固定**，始终嵌在柜体自下而上的三层，**不参与自动布局，也不随识别结果变化**：抽屉不是待收纳物品，不被推荐算法移动，`allowed_region_ids` 对其无意义。

- 抽屉的收纳区域是**内腔**：内部底面、四壁内侧与净高，按内腔实际尺寸定义，见第 2.2 节。
- 抽屉可沿柜体开口方向抽拉（本演示为 **-x**，即面板所在侧的向外方向）。行程由滑轨长度决定，不得超过滑轨可用长度，避免完全脱出。抽拉是用户交互，不是算法输出。
- 抽屉的运动不改变其初始位置记录；抽拉位移单独保存，不与 `position` 混用。

碰撞几何按第 2.2 节生成，其中开口空心壳（抽屉箱体）不得用凸包近似：凸包会填实内腔，破坏收纳区域。

## 2. 场景输入 `scene.json`

顶层必需字段：

| 字段 | 定义 |
| --- | --- |
| `schema_version` | 固定字符串 `"1.0"`；不兼容版本必须拒绝 |
| `scene_id` | 场景稳定 ID |
| `scene_revision` | 从 1 开始的整数，由后端在一次编辑提交成功后递增一次；变更范围见第 5 节 |
| `baseline_id` | 用户确认的原始快照 ID；确认前为 `null`，此时不能提交整理、走线或对比指南 |
| `template_id` | 场景模板 ID；参数化演示为 `demo_desk_v1`，固定家具为 `dormdesk-v1`；独立算法样例可使用明确命名的其他模板，不据此替代主模板验收 |
| `desk` | `{width_m, depth_m, top_height_m}`，均为正数；宽深为桌面包络范围，非矩形桌面的真实支撑由桌面高度的 `regions` 并集限定，不能把包络中的空区视为可用桌面 |
| `wall` | `{z_m, bounds_xy_m: [x_min, x_max, y_min, y_max]}`，给出后墙平面及面板可放置边界 |
| `items` | 下述物品数组，包括设备、插排、墙插与网口 |
| `regions` | 可摆放的桌面、四格书架与抽屉内部支撑面 |
| `obstacles` | 桌板、立柱、背板等固定碰撞体 |
| `reserved_zones` | 本次算法请求的禁入体积；物品摆放保留操作区与水杯区，产品走线请求按第 2.3 节留空 |
| `exposure_zones` | 用于计算桌面暴露线长的体积，字段为 `id`、`min`、`max`，不参与禁止通行判定 |
| `routing_graph` | 已配置的允许走线节点和边，包含穿线孔与固定点 |
| `cables` | 用户确认的线缆和连接关系 |

演示的“8 件物品”指 8 件待整理物品；插排、墙插和网口等基础设备另计，但均放入 `items` 并参与碰撞与结果输出。固定桌体结构放入 `obstacles`，不重复注册为物品。“3 根线”指 `cables` 中的 3 条连接，包含插排总线；H0–H4 的共同样例必须列明全部物品 ID、基础设备 ID 及三条起止接口，所有模块使用同一清单。

所有坐标、尺寸和数值必须有限，位置、方向和 `size_m` 为三元数组，边界数组长度按字段定义；物品尺寸、桌体尺寸、区域净高和通道净空为正数，边界下限严格小于上限。各类实体的 ID 在场景内全局唯一，所有引用必须存在。浏览器可为新物品和接口生成 UUID，后端验证唯一性后原样保存；后端创建的实体由后端生成 ID，双方均不得在保存时重新编号。场景 ID、快照 ID 与内部生成任务 ID 由后端分配。

### 2.1 物品

| 字段 | 定义 |
| --- | --- |
| `id`, `name`, `category` | 唯一 ID、显示名、类别；算法不使用名称作为主键 |
| `size_m`, `position`, `rotation_y_rad` | 按第 1 节解释 |
| `dimensions_source` | `user` / `template` / `estimated`，估计值需要用户确认 |
| `dimensions_confirmed` | 布尔值，表示用户已确认当前尺寸；来源与确认状态相互独立 |
| `fixed` | 是否禁止自动移动 |
| `usage_frequency` | `high` / `medium` / `low` |
| `placement_priority` | 可选整数 `0..100`，缺省为 `0`；数值越高越先摆放，先于允许区域数量、面积和使用频率，不放宽任何几何硬约束 |
| `allowed_region_ids` | 自动收纳的目标区域 ID，非固定物品必须非空；原位保留规则见第 3 节，固定墙面设备可为空 |
| `preferred_region_ids` | 可选无重复数组，必须为 `allowed_region_ids` 的子集；同组区域等价且无顺序。几何可行时优先选择组内区域，再优化连续桌面面积和取用成本；组内不可行时回退到其余允许区域。缺省或空数组沿用原评分 |
| `allowed_rotations_y_rad` | 自动推荐允许的朝向，1–8 个不重复的有限弧度，范围 [-π, π]，默认 0 与 π/2；固定 L 形桌的笔记本使用 -π/9（朝座位内转 20°）。手动朝向可为任意有限弧度，固定物品保持输入朝向 |
| `collision` | `type: "box"` 使用 `size_m` 与物品变换；`type: "compound"` 使用局部凸体部件并集，定义见第 2.2 节 |
| `ports` | 接口数组，字段见下文 |
| `image_url`, `model_url` | 图片与已归一化模型 URL，无资产时为 `null` |
| `generation` | `{task_id, status, source, error}`；无任务时 `task_id` 为 `null` |
| `plug_mount` | 可选 `{socket_port_id, plug_port_id}`，固定直插适配器的插排连接，见第 2.6 节；不表示柔性线缆 |

`generation.status` 为 `not_requested` / `queued` / `running` / `succeeded` / `failed`，表示当前内部任务状态；未请求时 `task_id` 为 `null`。`source` 为 `placeholder` / `live` / `cache`，描述当前显示外观的来源；没有可用资产时为 `placeholder`，内置或复用资产为 `cache`。`error` 为错误说明字符串或 `null`。重新生成期间和失败后保留已有可用外观及来源，没有旧资产才显示简化模型。同一任务状态只向终态前进，重提生成创建新 `task_id`；查询重试沿用原任务。供应商任务标识保留在后端适配器，不与内部 `task_id` 混用。模型替换不修改 `scene_revision`，因为规划几何不变；尺寸校正则必须修改版本。

接口字段为 `id`、`type`、`local_position`、`local_direction`、`capacity`、`confirmed`。`confirmed` 为用户已确认当前接口位置和类型的布尔值；`local_direction` 必须为单位向量。首版 `capacity` 为 1，插排每个插孔是独立接口。类型为 `power_source` / `power_sink` / `usb` / `network` / `hdmi`。电源线连接 source 与 sink，其他线连接同类接口，起止顺序不影响兼容性；USB 等复杂协议协商不在首版范围。

所有参与规划的物品须 `dimensions_confirmed: true`，走线引用的接口须 `confirmed: true`。尺寸编辑先置尺寸及全部接口为未确认；确认尺寸不会自动确认接口。接口位置、方向或类型修改后需重新确认，单纯平移或旋转整个物品保留局部接口确认状态。`dimensions_source` 不因用户确认而从 `estimated` 改成 `user`，只有用户实际输入替代尺寸时才改变来源。

前端可接收物品表面任意取点的世界坐标，按第 1 节逆变换写入接口的 `local_position`，表面法向转换为 `local_direction`，确认类型后再提交线缆；不另加与接口坐标重复的线缆端点字段。终点同样引用插排、墙插或网口的独立接口。

插排使用 `category: "power_strip"`，额外必需字段 `socket_count` 为 `4` / `6` / `8`，必须恰有相同数量的 `power_source` 接口，并有一个供插排总线使用的 `power_sink` 接口。选择规格时同步更新尺寸、碰撞体与接口；保留仍存在的接口 ID，移除接口上的线缆必须由用户重新指定，不能自动改接或静默删除。规格切换与改接作为同一次编辑提交：悬空引用只允许存在于客户端草稿，未修复前不保存为正式场景、不进入算法；取消则恢复旧规格和连接。提交成功后场景版本只递增一次，变更的尺寸与接口仍须确认。

照片识别需区分常用外设与待收纳杂物，用户确认后映射到现有 `category`、`allowed_region_ids` 和 `fixed`，不另加同义分类字段。键盘、鼠标、数位板允许区域为桌面中央；课本、水杯、收纳盒等允许区域为书架格或抽屉，具体区域 ID 由演示场景配置。

显示器、打印机等决定桌面结构的大型设备可配置更高 `placement_priority`，再通过 `allowed_region_ids` 表达后部主视区、侧部设备区等位置要求。优先级不等于使用频率，也不自动推断人体工学区域；用户确认的区域和尺寸仍是硬约束。未提供优先级的旧场景保持原有摆放顺序。

产品工作台默认显示器优先级为 100、打印机为 90。显示器按正面朝向的真实碰撞框，在键鼠活动区后方生成与其中线对齐的专用 `monitor-view-{物品ID}` 偏好区域；主视框超出桌面或侵入水杯区时不生成该偏好。自动移动候选只允许 0°，主视区受阻时可回退到其余允许的桌面区域，并在结果中明确提示未采用中央主视位；空间不足仍保留原位并报告失败。固定、锁定物品及合法手动原姿态的保留语义不变，保留的非主视姿态不会冒充已居中。多个显示器依次尝试各自主视区，后续设备可能回退，不代表实现了双屏布局优化。

打印机自动整理只允许桌面左右的 `printer-side-*` 设备区，朝向为 0°，先于收纳物和其它桌面物品安排；侧区排除键鼠列、显示器理想主视列、固定/锁定显示器的实际横向列及水杯区，不以显示器后方或地面兜底。侧区存在但无法容纳时保留原位并报告未安放；桌面完全没有侧区时在提交前给出调整配置的明确错误。区域不随可移动物品的原始姿态或应用变换改变，保持后端保存与应用一致；产品还按最终物品姿态复核打印机与显示器的横向关系，冲突结果不可接受。Mock 使用已经排定的显示器位置检查侧区，右侧被打印机占用时水杯可再尝试合法左侧位置。

产品工作台的默认区域策略按物品形状、类别、使用频率与收纳偏好生成，不把地面视作所有杂物的收纳目标。电脑主机可落地；收纳容器仅在非高频且用户明确选择桌下收纳时允许落地。书本、笔记本电脑、手机、台灯等普通物品与插排不生成裸地面目标，空间不足时保留原位并报告未安放。插排可使用实际横梁支撑。完整地面支撑区仍用于复查固定和残留物品，不等于允许自动落地。收纳偏好通过 `preferred_region_ids` 表达，不能依靠 `allowed_region_ids` 的排列顺序。

### 2.2 区域与碰撞几何

- `regions[]`：`id`、`surface_y_m`、`bounds_xz_m: [x_min, x_max, z_min, z_max]`、`clearance_height_m`。物品底面必须完整落在区域内，`position[1]` 等于支撑面高度，物品高度不超过净空。
- 四格书架每格单独配置区域；右侧抽屉区域使用内部底面、内边界与净高，内壁纳入 `obstacles`。抽屉的收纳区域为**内腔**，不允许通过忽略壁厚扩大收纳容积。抽屉按内腔生成可放置区域，抽拉能力与初始位置的约定见第 1.1 节。
- 墙插与网口使用 `category: "wall_socket"` / `"wall_network"`、`fixed: true`、`rotation_y_rad: 0` 和空 `allowed_region_ids`，不受水平支撑面限制；其底面中心 Z 等于 `wall.z_m`，面板 X/Y 投影必须在 `bounds_xy_m` 内。仍参与物品与障碍碰撞检查，用户只可沿墙面平移，不旋转面板。其他物品的 `fixed` 同样只禁止自动移动，不禁止用户手动编辑。
- `obstacles[]` 与 `reserved_zones[]`：`id`、`min: [x,y,z]`、`max: [x,y,z]`，均为世界坐标 AABB。区域接触作为支撑处理，体积相交作为冲突处理；几何容差固定为 0.001m，不能用容差豁免明确的穿透。
- 可选 `constraints: {min_item_gap_m}`：物品之间的最小水平净距，有限非负米数；缺省为 0，产品整理默认 0.02m。只比较 Y 区间有正重叠的真实凸体部件之间的 XZ 凸投影最短欧氏距离，刚好达到阈值合法；旋转与复合体空隙保留。该模型对竖直棱柱精确，对倾斜凸部件保守，可能拒绝同高度实际更宽的空隙。固定与未安放物品同样参与最终复查。仅明确 `plug_mount` 引用的插排/适配器配对豁免净距，实体碰撞与插接检查仍生效；不额外要求家具、桌边或区域边界留出该距离。间距不足单独返回 `item_spacing`，空间不足不能缩小净距或忽略残留物品制造成功。
- 产品整理以 `reserved_zones` 保留每个有效穿线孔的桌上出线空间：孔外接方盒每侧增加 0.01m，桌面向上 0.05m。该区防止物品盖住孔口，不作为线缆禁入区；产品走线仍使用 `reserved_zones: []`。
- `items[].collision`：`type` 为 `"box"` 或 `"compound"`，二者互斥，按 `type` 分支解释。
  - `"box"`：不写额外字段，几何由 `size_m` 与物品变换推导；保守包围圆柱、锥体等非长方体物品。
  - `"compound"`：写 `parts[]`，每个 `part` 为 `{vertices_m: [[x,y,z], ...], faces: [[i,j,k], ...]}`，即物品**局部坐标系**下的凸多面体，面为三角形顶点索引。所有部件共用物品底面中心锚点，局部轴与 `rotation_y_rad` 前的物品朝向一致；世界几何 = 绕 Y 旋转 `rotation_y_rad` 后平移到 `position`，坐标变换与第 1 节一致。`size_m` 仍描述整体尺寸，显示模型替换不改动这些数据；数据生产方须按确认尺寸归一化并正确设置锚点，不能把外观网格的任意原点当作物品底面。
  - 校验：`parts` 为 1..128 个；每个 part 4..128 个顶点、4..256 个三角形面；坐标全部有限；顶点不得重复；索引必须合法；面必须向外且一致定向，构成闭合流形与凸体；体积为正。部件可以重叠。容差 `1e-7`。几何容差与 `obstacles` 一致为 0.001m。
  - 各部件实体的并集参与布局碰撞、走线搜索与最终曲线复查，部件之间的空隙不视为实体，但仍须满足线径、容差和通道约束。
  - 渲染几何与碰撞几何必须同源：可见实体与 `parts` 由同一份实体描述符导出，不允许出现"看得见的是 A、算碰撞的是 B"。显示器、台灯等带支杆的物品应给出分离实体，使支杆之间的空隙在碰撞中保持为空，而不是被整体包围盒填实。
  - `"compound"` 只描述物品自身凸体；固定家具（桌面板、桌腿、桌下横梁、书架搁板与侧板、立柱）与抽屉属于场景固定结构，按第 2.2 节 `obstacles[]` 表达，二者共同参与碰撞检查。抽屉箱体为开口空心壳，须按底板与侧壁分割表达，使内腔保持为空（见第 1.1 节）。
  - **摆放搜索与摆放验收必须使用同一碰撞几何**：区域适配、净空高度、活动区避让、邻位间隙与包围盒面积口径一律按真实碰撞体计算，不能只在最终校验时换成真实体积。`size_m` 保留为声明尺寸（界面展示、锚点与排序启发式使用），不得作为几何判定依据：否则声明比实际宽的物品（台灯、显示器）会被无谓地排除，声明比实际窄的物品会被放进放不下的位置。搜索期的尺寸应与真实体积一致，端到端由回归脚本断言。
- 桌板穿线孔必须同时体现在桌板碰撞体分割和走线通道中，不能仅给封闭桌板添加路径节点。
- `routing_graph.path_style` 可选 `smooth` / `orthogonal`；产品默认使用 `orthogonal`。正交图每条边必须沿单一坐标轴。
- `routing_graph.nodes[]`：`id`、`position`、`kind`，kind 为 `corner` / `slot` / `fixing_point` / `endpoint`。
- `routing_graph.edges[]`：`id`、`from_node_id`、`to_node_id`、`modes`、`clearance_radius_m`、`exposed`；边首版表示直线通道，需通过碰撞检查，净空半径不得小于线缆半径。`modes` 为 `slot` / `backboard` 的非空子集，图边为双向。
- `slot` 路径必须经过 `kind: "slot"` 的实际开孔通道下行；背板后通道以 `fixing_point` 节点与允许 `backboard` 的边配置，路径必须绕至背板后下行。两种模式的完整通道均需在演示场景配置，不能仅通过更改输出标签表示不同策略。
- 多线缆允许在同一通道汇聚，必须为线缆体积安排不相交的位置并复查共享通道净空。单个插孔的容量规则不因汇聚而改变；通道不足时返回 `no_path`。
- 设备接口通过经碰撞检查的引出段连接到图。`box` 从真实接口沿世界接口方向发出射线，取离开所属 OBB 按“线缆半径 + 0.001m + 0.0005m 曲线采样误差”膨胀后的首个出口。`compound` 先识别实际包含接口的部件；接口紧贴外壳之外且仍位于线缆净空带内时，只允许其朝外法向正后方最近的壳体成为所属部件，再按同一余量膨胀求出口。前方独立部件与其余部件始终检查碰撞，不能把相邻部件合并豁免。出口沿射线再留 0.001m 余量，接口至出口的直线扫掠体是唯一允许豁免所属部件碰撞的有限引出通道。曲线端点仍为真实接口，起始沿起点朝外方向离开，末尾沿终点朝外方向的反向进入；其余曲线不得再次穿过自身。通道始终检查其余部件、其他物品、障碍及本次请求的禁入区，受阻返回 `endpoint_blocked`，不能整体忽略所属设备。此处理可能保守拒绝穿过相接部件的内部引出，不把部件间隙自动推断为插头通道。
- `routing_graph.edges[].exposed` 仅用于搜索偏好，不作为暴露线长的统计依据；统计始终按 `exposure_zones` 并集计算。

### 2.3 线缆输入

每条线缆必需字段为 `id`、`start_port_id`、`end_port_id`、`cable_type`、`thickness`、`length_m`、`diameter_m`、`min_bend_radius_m`、`slack_m`、`mode`。

- `cable_type`：`power` / `usb` / `network` / `hdmi`，用于连接类型校验。
- `thickness`：`thick` / `thin`，产品两档外径分别为 0.0065m / 0.0035m，影响线缆碰撞体、净空、线间距与显示粗细，不再附带物理最小转弯半径。
- `min_bend_radius_m`：有限非负数；正交路径必须传 `0`。直角布局表达安装意图，不代表物理线缆转弯半径认证。
- 粗线预设覆盖台式机/显示器电源线、网线与插排总线，细线预设覆盖充电线、外设连接线；粗细可单独选择，不能仅依据电气类型强制指定。渲染半径为可视放大值，不作为碰撞半径。
- `length_m` 是已知的现有线材长度，未知时显式传 `null`；规划不向用户索取线长。算法始终计算已验证曲线的 `path_length_m`，所需备线长度为 `path_length_m + slack_m`。仅当 `length_m` 已知时检查是否足够，超出则返回 `length_exceeded`。未知时仍完成几何、接口及已启用的曲率/支撑复查，不宣称现有线材长度足够，也不能用虚构的大数代替未知值。
- 非 `null` 的 `length_m` 和 `diameter_m` 必须有限且大于零；`min_bend_radius_m`、`slack_m` 必须有限且非负，直径与半径字段不接受 `null`。线缆起止接口不得相同。多条请求同时超出某接口容量时，所有引用该接口的冲突线缆均返回 `port_occupied`，不按数组顺序保留一条；无冲突线缆继续规划。
- 产品走线请求将 `reserved_zones` 设为 `[]`：打字区、水杯活动区和桌下腿部区不再阻挡线缆；物品整理请求中的活动区硬约束保持原样。独立领域场景显式提供禁入体积时仍按该输入复查。产品图优先提供沿桌后缘的并排通道，通过非暴露边降低搜索代价；此偏好不能豁免家具、物品、线间净空、接口、长度或策略约束。
- `mode`：首版必须支持 `slot` 与 `backboard`。对应实现或通道缺失时返回 `unsupported_mode`，仍属于该策略验收未完成，不能改走另一策略后标记成功。
- 原始线缆可选 `baseline_path_points`，为至少两个世界坐标点组成的实测或用户确认折线；只在建立基线时写入，后续当前场景中的同名值只读复制自该快照。基线确认时未提供则保持未知，后补原始路径须显式建立新基线，不回写旧快照。

### 2.4 走线支撑与固定件

实际布线应沿桌面、柜体、孔边或已安装的固定件收拢。`routing_graph` 可增加下列字段，开启支撑硬约束；仅有 `fixing_point` 节点或靠近桌底，不代表存在可固定线缆的硬件。

```json
{
  "support_policy": {"max_unsupported_span_m": 0.23},
  "supports": [
    {
      "id": "underside_tie_0",
      "kind": "cable_tie",
      "obstacle_id": "desk_top",
      "face": "y_min",
      "bounds_uv_m": [0.19, 0.23, 0.13, 0.17],
      "stand_off_m": 0.02
    }
  ]
}
```

这是 `routing_graph` 的字段片段，引用的障碍必须存在于完整场景。策略上限为有限正数，表示沿连续曲线测量的最大无支撑跨距；0.23m 仅是样例参数，实际需按线缆和安装条件确认。提供 `supports` 时必须提供策略；仅提供策略等价于空支撑集合。旧场景未提供策略时保留几何规划，但支撑状态为 `not_evaluated`，不能当作安装可行性已验证。

| 支撑字段 | 约定 |
| --- | --- |
| `id` | 场景内全局唯一 ID |
| `kind` | `surface`：向上承托面；`cable_tie`：已安装扎带/线夹；`cable_tray`：已安装连续集线槽/托盘，不表示电气集线器 |
| `obstacle_id` | 安装所依附的固定障碍 ID，不引用显示网格或可移动物品 |
| `face` | `x_min` / `x_max` / `y_min` / `y_max` / `z_min` / `z_max`，引用障碍 AABB 的真实表面 |
| `bounds_uv_m` | `[u_min, u_max, v_min, v_max]`，采用世界坐标；切向轴按 X/Y/Z 顺序去掉面法向轴，例如 Y 面为 X/Z、X 面为 Y/Z。范围必须完整位于该面内，扎带每个切向边长最多 0.05m |
| `stand_off_m` | 从安装面沿外法向的可承托/夹持范围，有限正数；原型上限分别为 surface 0.02m、扎带 0.05m、托盘 0.10m |

`surface` 只允许 `y_max`；竖直面和桌底必须配置已安装的扎带或托盘。可在桌沿、孔边和柜侧设置多个局部支撑范围，桌底托盘可覆盖连续通道。支撑带不会豁免障碍、保留区或其他线缆碰撞；检查完整线缆体积能否落入带内，并计入曲线近似误差。端点引出段和转弯也计入无支撑跨距，曲线分段不能重置跨距。

支撑检查是基于用户确认安装条件的保守几何模型，不模拟重力下垂、张力、扎带承载力或施工安全；增加一个 JSON 固定件不代表现实已安装。

产品工作台在 `RoomConfig.cableManagement` 持久化 `{mounts, verifySupport, maxUnsupportedSpanM}`。`mounts[]` 保存 `id`、`label`、`kind`、真实固定障碍的 `obstacleId`、`face`、前端世界坐标的 `boundsUvM`、`standOffM`、`installed` 及可选预设标识 `preset`；这些是产品编辑状态，导出正式请求时转换为上面的 snake_case 字段与算法世界坐标，不向领域接口重复增加同义字段。桌后理线扣、桌下扎带和集线槽预设从当前真实桌板推导，添加时一律 `installed: false`。安装面失效时要求移除或重新配置，不能把配件转移到虚构表面。

`verifySupport` 默认 `false`，关闭时正式请求省略 `supports` 与 `support_policy`，待安装集线槽候选仍可单独提交；用户显式开启后才按 `maxUnsupportedSpanM` 复核跨距。只有 `installed: true` 的有效安装件可成为 `supports`，待安装建议不能补足当前支撑。配件添加、删除、确认安装、复核开关及跨距变化均使旧走线失效，撤销/重做也不得恢复旧认证。关闭复核时不宣称支撑验证通过。

### 2.5 可选集线槽优化

集线槽用于收束多根线。先以当前已安装的承托/固定条件逐根规划并复查，再识别可以共同收入集线槽的平行桌下区段。可选 `routing_graph.tray_candidates[]` 描述允许安装的位置，字段沿用支撑的 `id`、`kind`、`obstacle_id`、`face`、`bounds_uv_m`、`stand_off_m`，其中 `kind` 固定为 `cable_tray`、`face` 固定为 `y_min`，另有必需的 `cable_ids`（至少两条不重复的现有线缆 ID）。安装范围、离面上限和全局 ID 规则与第 2.4 节一致。

候选不属于已安装 `supports`，不要求开启支撑策略，也不参与当前路线的支撑判定。没有候选或没有可合并区段时，保留逐线方案及原有成功/失败状态。当前优化只评估候选位置内已经规划好的线路，不为放入槽内而改变端点、延长路径或忽略线缆间占用。

接受建议时，应用层记录该配件已安装，并将其移出 `tray_candidates`；用户显式开启支撑复核后，正式请求去掉 `cable_ids` 并将其作为已安装 `supports` 提交。只有用户确认安装后才可使用这一事实。该编辑须递增 `scene_revision`，重新规划并验证。安装动作与原子保存仍由应用层负责，领域算法只输出建议。

产品的 `Project.cableTrayAnalysis` 缓存后端结果的 `{sceneId, sceneRevision, optimizations}`，不改变领域输出。只有所有当前线缆的认证场景与版本均匹配、且没有 `stale` 线缆时，面板才展示推荐成员、共享长度、槽宽与未采用原因。配件即使没有有效走线也可显示安装位置；推荐结果本身不改变 `installed`。

### 2.6 插排上的直插适配器

`category: "power_adapter"` 的物品可声明 `plug_mount: {socket_port_id, plug_port_id}`。本轮仅支持固定适配器插在固定 `power_strip` 的向上插孔上：`socket_port_id` 引用该插排的 `power_source`，`plug_port_id` 引用适配器自身底面的 `power_sink`，两端接口均须确认。插排与适配器必须 `fixed: true`，不能自动单独移动或把该关系解释为柔性电源线。

插接复查使用物品的当前变换：两端世界位置在 `0.001m` 容差内一致、方向相反，插孔位于插排顶面、适配器插头位于自身底面，适配器底面与插排顶面接触。原型还要求适配器至少一半底面积落在插排顶面内、每侧悬挑不超过 `0.02m`，插排自身至少有一个合法支撑区域，适配器继承其剩余净高；这些是保守示例约束，不是实测适配器规格。所有物品、障碍及操作区碰撞照常检查，不开放普通物品堆叠。初始可移动物品的重叠仍可由整理修复，走线只接受安装本体无碰撞的当前场景。

直插连接占用两个接口的容量。同一插孔或插头不能声明多个直插关系；柔性线缆再引用任一已占用接口时返回 `port_occupied`。适配器输出线应引用它的独立输出接口。适配器本体仍参与其他插孔的引出净空检查，不能只靠连接类型和插孔数量判断能否插入。错位、穿透、未确认或悬空引用不能作为有效安装保存或用于规划。

## 3. 整理输出 `packing_result.json`

```json
{
  "schema_version": "1.0",
  "scene_id": "scene_demo",
  "scene_revision": 3,
  "status": "success",
  "items": [
    {
      "item_id": "laptop_1",
      "name": "笔记本电脑",
      "model_url": null,
      "current_pos": [0.9, 0.77, 0.35],
      "target_pos": [0.725, 0.77, 0.3],
      "target_rotation_y_rad": 0,
      "target_region_id": "desk_primary",
      "placement_status": "placed",
      "reason_code": null
    }
  ],
  "issues": []
}
```

示例只含一个物品，实际输出必须覆盖输入 `items` 的全部物品，包括另计的基础设备。`current_pos` 是本次输入的位置，不是原始快照位置。`target_region_id` 引用输入区域；固定墙面设备返回 `unchanged`、原变换及 `target_region_id: null`，不能虚构水平支撑面。

每条物品结果包含 `name` 与 `model_url`，分别复制当前输入物品的显示名和已归一化独立资产路径，无模型时为 `null`；前端仍按 `item_id` 匹配，不以名称为主键。`current_pos` 与 `target_pos` 分别满足附件要求的整理前坐标和目标坐标。以上载荷可序列化下载为 `packing_result.json`，不要求后端和算法通过磁盘通信。

顶层 `status` 为 `success` / `partial` / `infeasible`：全部满足收纳要求为 success，存在未安放物品但整体仍无冲突为 partial，无法给出满足硬约束的布局为 infeasible。每件物品 `placement_status` 为 `placed` / `unchanged` / `unplaced`。后两种的目标位置与朝向保持输入值；`unplaced` 需带原因，目标区域无法确认时为 `null`，且继续参与最终场景碰撞检查。

`allowed_region_ids` 与自动朝向限制约束推荐的 `placed` 目标；`unchanged` 用于固定物品或已满足目标而无需移动的物品。`unplaced` 可以留在不属于收纳目标的原支撑面，例如仍在桌面的杂物；这是未完成收纳，不是成功落位。它仍必须满足真实支撑、边界、净高、不碰撞和不占保留区等几何硬约束，`target_region_id` 填实际原支撑面；无法确认合法原位时只能返回 `infeasible`。指南和指标不能忽略残留物品。

仅当整个输出布局满足硬约束时才能应用；`partial` 表示部分物品未能收纳但整体仍无冲突。`infeasible` 不应用任何移动，返回保持输入变换的结果及具体问题。应用有效布局后场景版本递增，后续走线使用新版本重新计算。

## 4. 走线输出 `cable_routing.json`

```json
{
  "schema_version": "1.0",
  "scene_id": "scene_demo",
  "scene_revision": 4,
  "status": "infeasible",
  "cables": [
    {
      "id": "cable_laptop_power",
      "start_port_id": "pdu_socket_1",
      "end_port_id": "laptop_power",
      "cable_type": "power",
      "thickness": "thin",
      "mode": "slot",
      "diameter_m": 0.004,
      "status": "failed",
      "curve_segments": [],
      "path_points": [],
      "path_length_m": null,
      "reason_code": "length_exceeded"
    }
  ],
  "metrics": {
    "exposed_length_m": null,
    "baseline_exposed_length_m": null
  },
  "issues": [
    {
      "entity_id": "cable_laptop_power",
      "code": "length_exceeded",
      "message": "当前线长不足，需调整设备或使用更长线缆"
    }
  ]
}
```

结果覆盖全部请求线缆。顶层 `status` 为 `success` / `partial` / `infeasible`：全部有效为 success，部分有效为 partial，全部失败为 infeasible。上例展示一根线缆因长度不足而失败的完整响应。

单线 `status` 为 `valid` / `failed`。有效路径 `path_points` 是已平滑并复查的世界坐标采样点，至少两个点，首尾与对应接口一致；`path_length_m` 为实际验证曲线的弧长，`reason_code` 为 `null`。渲染器按采样点绘制已验证路径，不再擅自使用另一条可能穿模的插值曲线。

`curve_segments` 为必需数组，保存已验证的世界坐标段，每段为 `{control_points: [P0, P1, P2, P3]}`。`orthogonal` 路径的四个控制点必须共线，内部段必须轴向，段间只允许位置连续的直角转向；`path_points` 与这些段一一对应，长度按折线复查。`smooth` 场景继续使用三次 Bézier 连续曲线约定。

失败时 `curve_segments` 和 `path_points` 均为 `[]`，长度为 `null`，并包含原因。`min_bend_radius_m > 0` 时依据连续曲线校验曲率，不能把采样点间的折线尖角视为符合半径要求；为 `0` 时只取消该物理最小值，不取消曲线连续性。碰撞检查应覆盖曲线与采样点之间的线缆体积，而不只是点本身；验证需保守覆盖采样近似误差。算法实现时记录采样误差与弧长积分精度，并提供成功与失败 JSON 样例供前端解析和下载为 `cable_routing.json`。

单线可附加 `support_check: {status, max_unsupported_span_m, support_ids}`。`status` 为 `verified` / `not_evaluated`；开启策略且最终连续曲线通过支撑复查时才能为 `verified`，跨距字段为有限非负弧长上界且不超过输入策略，`support_ids` 只列实际承托了正长度曲线的支撑 ID。失败或未评估时跨距为 `null`、ID 数组为 `[]`；旧结果省略该对象同样表示未评估。无支撑部分按 Bézier 控制多边形长度的保守上界累积，不以较短的采样弦长冒充跨距；无法在细分预算内证明通过时失败。

走线结果可附加 `underside_tray_optimizations[]`，每项字段如下；它与单线结果分开，不改变 `cables` 的有效性、几何或指标。

| 字段 | 约定 |
| --- | --- |
| `id` | 本结果内唯一的优化条目 ID |
| `status` | `recommended`：未安装候选有可共同收入的路线；`verified`：已安装槽内有通过支撑复查的组合；`not_used`：本候选/已安装槽没有满足条件的组合 |
| `support_id` | 已安装支撑 ID 或 `null`；推荐不引用已安装支撑 |
| `cable_ids` | 组合中的有效线缆 ID，推荐/已验证至少两条；失败线缆不进入组合 |
| `shared_length_m` | 同一平行区段的保守纵向重叠长度，不是各线长度之和，也不宣称节省线长 |
| `occupied_width_m`, `available_width_m` | 组合现有曲线含线径与误差余量的横向包络宽度、槽安装范围的横向宽度；无组合时占用宽度可为 0 |
| `requires_installation` | 推荐为 `true`，已安装组合为 `false`；不代表自动执行了安装 |
| `reason_code` | 正常组合为 `null`；未采用可为 `no_compatible_routes` / `insufficient_width` / `not_evaluated`，不进入场景几何 `issues` |
| `mount` | `{obstacle_id, face, bounds_uv_m, stand_off_m}`，可审核的桌底安装位置 |

当前实现只识别已配置候选范围中的平行共享区段，以最终 Bézier 凸包和线缆体积作保守检查；不把只交叉一次、碰到同一槽或同名固定点视为可合并。优化是收束与安装建议，不是电气混排、承载或安全认证。

`metrics.exposed_length_m` 是所有有效当前路径在 `exposure_zones` 并集内的弧长之和；没有任何有效路径时为 `null`。只有所有请求线缆都提供 `baseline_path_points`，才能用相同规则计算 `metrics.baseline_exposed_length_m`，否则为 `null`。失败线缆不贡献当前暴露线长，未知基线不能按零处理。该指标由走线算法计算，前端不自行估算。

附件“任意两点成功生成样条”表示接受任意合法表面点并在约束可行时生成路径，不承诺穿越障碍或突破线长限制；不可行条件仍必须返回失败。

## 5. 版本、错误与结果有效性

后端是正式场景和版本的唯一权威。客户端编辑是草稿，提交时携带预期版本；后端校验后原子保存并返回新场景。名称、类别、尺寸与确认状态、位置、接口、连接、区域、障碍、规划条件（包括摆放优先级、直插关系、支撑策略和固定件）、物品增删或 `baseline_id` 改变时，版本递增；仅生成状态和外观 URL 更新不递增。无效或取消的编辑不递增。保存整份场景时必须合并后端当前外观与任务信息，不能由旧客户端副本回退生成进度。

规划接收与应用遵循以下规则：

1. 未保存草稿存在时不能应用规划结果；客户端只接受 `scene_id`、输入 `scene_revision` 均匹配正式场景的建议。输入变化后丢弃旧建议，由用户重新触发规划，避免自动重试循环。
2. `packing_result` 的版本始终是输入版本 n；接受建议后后端只应用目标变换，原子生成 n+1，原建议作为已消费的历史来源保留，不能再次应用或改写版本伪装成新结果。应用时不复制结果里的 `name`、`model_url` 或整份旧物品数据。
3. 当前布局是否有效由当前场景重新校验，指南的物品移动从原始快照与当前场景的差异生成，不要求历史布局建议仍匹配当前版本。后续仅编辑接线时无需重新整理，但须复查当前布局并重新走线。任意版本变化都使旧走线、比较指标与指南失效，首版重新验证全部请求线缆。
4. 后端保存规划、接受布局或发布指南时都在事务内复核场景 ID 和预期版本；前端丢弃旧响应不能代替后端检查。规划与指南发布本身不递增几何版本；应用布局才递增。

原始快照保存其确认时的完整场景，建立时所有物品尺寸及已有连接引用的接口必须确认，之后不可变。重新建立基线生成新 `baseline_id` 并递增当前版本；物品或连接集合改变后，旧基线仍保留，但比较按第 6 节标记不可比，不靠删除基线实体制造改进。

模型生成结果按场景 ID、物品 ID 与当前 `task_id` 匹配，仅替换外观，不能回写提交任务时的旧变换；已删除物品或被新任务替代的结果不再应用。同一版本的轮询响应也须按任务 ID 和状态前进规则合并，不能用较早的 `running` 响应覆盖已完成资产。

`issues[]` 统一结构为 `{entity_id, code, message}`，其中场景级问题的 `entity_id` 为 `null`。物品 `reason_code` 和线缆 `reason_code` 使用相同错误码集合：

| 错误码 | 含义 |
| --- | --- |
| `invalid_input` | 缺失字段、非法尺寸、未知 ID、重复 ID 或不兼容协议版本 |
| `no_space` | 无符合摆放约束的位置 |
| `collision` | 最终布局或路径存在碰撞 |
| `item_spacing` | 布局中物品的水平净距不足 |
| `incompatible_ports` | 接口与线材类型不兼容 |
| `port_occupied` | 接口容量已占满 |
| `length_exceeded` | 路径与余量超过线长 |
| `endpoint_blocked` | 接口引出通道被遮挡 |
| `no_path` | 无满足净空、弯曲或禁入区条件的路径 |
| `unsupported_mode` | 策略未实现或对应通道未配置 |
| `unsupported_span` | 无支撑跨距超过配置上限，或在细分预算内无法证明支撑条件满足 |

协议版本、结构或 ID 引用错误在入口拒绝，不进入算法；具体 HTTP 状态由后端接口实现统一记录。供应商失败通过 `generation.error` 返回服务错误信息，不冒充几何规划失败。

## 6. 比较指标与指南数据

B 汇总独立比较载荷，A 用同一载荷展示指标，指南引用同一次比较；它不嵌入 C、D 的历史建议，也不另用一套统计口径。必需字段如下：

| 字段 | 定义 |
| --- | --- |
| `schema_version`, `scene_id`, `scene_revision`, `baseline_id` | 当前场景与基线标识，均遵循前文定义 |
| `area_grid_cell_m` | 首版固定为 `0.01`；面积比较双方采用同一网格 |
| `baseline_free_area_m2`, `current_free_area_m2` | 基线和当前主桌面最大连续可用面积，有限非负数；不可比时基线值为 `null` |
| `baseline_exposed_length_m`, `current_exposed_length_m` | 基线和当前全部请求线缆的桌面暴露总弧长，有限非负数或 `null` |
| `issues` | 当前场景的布局复查及本版本走线结果问题，沿用 `{entity_id, code, message}` |
| `unresolved_issue_count` | 当前 `issues` 按 `(entity_id, code)` 去重后的数量；不混入历史失败建议 |
| `comparison_note` | 不可比或未知值的原因字符串，全部可比时为 `null` |

面积统计范围固定为主桌面：在 X/Z 世界原点对齐的 0.01m 网格上，统计完全落在桌面矩形内、且不与桌面物品底部投影或该支撑面上的保留区相交的格子，取最大四邻接连通分量面积；格线接触不算体积占用。桌面物品指底面高度与 `desk.top_height_m` 在几何容差内一致的物品，保留区在 `min[1] <= desk.top_height_m < max[1]` 时投影为占用。书架、抽屉不累加到桌面面积，不同高度的悬空结构不投影为桌面占用。C 的面积函数对基线与当前场景分别计算，不能用“本次算法输入与目标”的面积冒充原始前后比较。

任一基线线缆路径未知时，基线暴露总长为 `null`；任一当前请求线缆失败或缺少本版本验证结果时，当前总长为 `null`，不能把失败空路径按零计入。没有请求线缆时总长为 0。基线折线按线段与暴露区域并集的交段长度计算，当前值按 D 已验证曲线弧长计算；两侧使用相同暴露区域，重叠区域不重复计数。

物品 ID 集合、确认尺寸、桌面尺寸或保留区改变时，面积比较不可比，基线面积返回 `null`；线缆 ID、起止接口、物理线材参数或 `exposure_zones` 改变时，线长比较不可比，基线线长返回 `null`。当前值仍按当前场景计算，`comparison_note` 说明变化；重新建立基线后才恢复对应比较。仅改变走线 `mode` 不影响基线可比性。任一比较值为 `null` 时不展示该项改进比例，基线为 0 时也不计算百分比。

指南绑定以上四个标识，由基线到当前的实际变化、当前布局复查及当前版本走线结果生成；包含搬动顺序、连接、穿线孔/固定点、线长与未解决事项。部分成功可导出带有“未完成”标记的指南，失败线不得有可执行穿线步骤；历史指南可查看但必须标记过期，不能作为当前有效方案。
