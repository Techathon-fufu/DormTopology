# 工作流与预制模型分支整合验收

日期：2026-10-17。整合分支：`codex/merge-workflow-prefab`，基于 `origin/main` 的 `b9685b5`，合入 `feat/desk-split-prefab-items` 的 `6b4b913` 与 `codex/real-workflow-loop` 的 `0b3f189`。保留两条来源分支的提交历史。

## 合并结果

- 产品工作台保留 main 的后台整理任务、版本同步与原子应用接口，前缀仍为 `/api/v1`。
- 独立 `/workflow` 保留完整契约场景、基线确认、实时整理、当前版本走线、对比与 Markdown 指南，API 调整为 `/api/v1/workflow`，避免同名场景和健康检查接口互相覆盖。
- 统一应用工厂通过 lifespan 创建和关闭两套服务。工作流使用独立 SQLite 文件，默认在产品数据库同目录的 `workflow.sqlite3`；照片位于同级 `workflow-data/photos/`。环境变量可分别设置。
- 桌体按贡献者交接采用 body + 三只独立抽屉，抽屉施加桌体的同一归一化矩阵，保留 main 的材质修正与源资产。
- 12 个单品 GLB 和生成碰撞数据保留；修正底心模型与父级半高偏移叠加，模型和碰撞同步匹配编辑后的尺寸。模型实例保留源根节点变换，切换资源时不显示旧实例。
- 抽屉取消操作不再被当作点击；结束操作检查指针 ID，防止重复结束。侧视机位改为室内斜前方，避免墙和示例物品遮挡抽屉正面。
- 正式抽屉测试等待动画收敛并检查真实指针操作。画面检查改用覆盖、亮度方差和空间分布，拒绝空白或均匀画面，不依赖资产配色数量；等待桌体资产加载后再检查。
- 删除贡献者明确标记“用后删除”的 5 个临时脚本/探针；保留正式资产、抽屉、产品整理与工作流测试。

## 实际验证

- 前端 TypeScript 与生产构建通过；有既有 Three.js 主包体积提示。
- `check-prefab-model.ts`：解析 12 个真实 GLB，108 组原生/非原生尺寸、底面与 Y 旋转碰撞检查通过。
- `check-desk-model.ts`：桌体 46 个保留部件、三抽屉的网格/材质/装配及 300mm 行程检查通过。
- `check-demo-seed.ts`：种子 v4、17 件示例及迁移边界检查通过。
- 后端全量 186/186 通过（约 282 秒）。随后增加应用实例隔离与启动前不创建资源的回归，再执行工作流 13/13 通过；全量与新增检查分两次运行。
- 工作流桌面/模拟 Pixel 7 的真实算法、三线成功、失败线缆、版本冲突、指南下载、照片非法输入和刷新恢复已通过。最终跨入口浏览器回归结果另记于下方。

本轮前端地址为 `http://127.0.0.1:5174`；默认 8000 端口已有进程，整合后端使用 `127.0.0.1:8001`，前端通过 `VITE_DEV_API_TARGET` 连接。产品真实整理验收另使用 5175 前端，设置 `VITE_ORGANIZATION_API_MODE=real`。测试数据位于 Git 忽略的 `.work/merge-prefab/runtime/`，没有改写原 `backend/data/`。标准启动方式仍见[后端说明](../backend/README.md)与[工作流说明](closed_loop_acceptance.md)。
