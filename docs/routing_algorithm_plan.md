# 走线算法实现规划

本文是成员 D 的首版实现计划。字段、单位、坐标系和状态枚举以[数据契约](data_contract.md)为准；本文只补充算法内部的处理顺序、搜索策略和验收规则，不另建一套接口协议。

截至 2026-10-17，走线业务核心已迁入 `backend/app/domain/routing/`：规范入口为 `plan_routing(scene)`，`plan_routes` 是同一函数的兼容名称；曲线工具位于该包的 `geometry.py`，测试位于 `backend/tests/test_routing.py`。旧 `algorithm/cable_routing/` 仅保留兼容导出，领域层不依赖旧包。当前覆盖端口/引用校验、A* / Dijkstra、双策略配置图、Bézier 曲线与基础汇聚/指标，并补充完整终点代价、汇聚曲线段间切向连续性和输入拒绝回归。产品已接真实后台任务及版本保护；新家具上的完整双策略、4/6/8 全规格、含插排总线的三线流程和实际安装支撑仍按任务清单验收。

## 1. 目标与边界

算法接收用户确认后的当前场景，分别为每条线缆规划 `slot`（穿线孔）或 `backboard`（背板后）路径，并返回已经完成几何复查的三维曲线。算法只返回建议，不修改物品位置、接口或线缆连接；物品移动、尺寸修改、插排规格切换或通道配置变化后，由后端递增 `scene_revision` 并重新调用。

首版采用配置好的稀疏通道图，不从桌体网格自动推导任意通道。图节点和边必须真实对应穿线孔、背板后通道、桌沿、线槽或固定点；不能只切换结果中的 `mode` 标签来模拟另一种策略。

2026-10-17 补充实际安装约束：配置支撑策略后优先沿桌面、孔边及柜侧的承托/固定范围走线，并把连续无支撑跨距作为硬约束。桌底和竖直面需要已安装扎带或连续集线托盘，不能仅凭贴近结构判断可固定。字段与安装范围只在[数据契约第 2.4 节](data_contract.md#24-走线支撑与固定件)定义；无策略的历史输入明确返回支撑未评估。

同日产品规则调整：粗细仅控制实际线径与净空，工作台传 `min_bend_radius_m: 0`，不设物理最小弯曲半径；正数领域输入继续复查曲率。产品不再把打字、水杯与腿部活动区作为线缆禁入体积，物品摆放约束不变。图搜索优先沿桌后缘的并排通道；真实碰撞、接口方向、长度、策略与线间净空继续检查。理线扣、扎带及桌下集线槽可在产品配置并确认安装，支撑硬约束由用户显式开启，默认关闭。

2026-10-18 配合物品 20mm 净距布局补充产品稀疏图：真实穿线孔内提供有限并排候选，孔边净空按保守内接方形的剩余宽度缩小；桌后缘和孔口上方提供距桌面 12/21/30mm 的跨线层，孔口上方的额外跨线点使用 `corner`，只有真实孔口顶面及下方节点使用 `slot`。对已连接、桌面附近的水平接口，沿出射法向外移 40mm 后提供上抬 15/30mm 的两个局部接入点，每点最多连接 8 个邻近桌面通道；接入点也不能代替孔或背板策略节点。所有边及最终曲线仍复查真实实体、线间净空和已启用的支撑策略，不扩大开孔、不豁免碰撞，也不表示已安装固定件。延长接口引出段的单次搜索直接避开已有线缆，防止反复选择被占用的入口；每线每轮最多 5 次搜索及最多两轮的预算不变。完整默认场景验证见[本地部署](local_deployment.md#4-当前版本验证)。

## 2. 输入形式

### 2.1 后端传入的场景

后端把完整的当前 `scene.json` 传给算法。走线需要读取以下字段：

| 输入部分 | 用途 |
| --- | --- |
| `schema_version`、`scene_id`、`scene_revision` | 协议和结果有效性校验，原样写入结果 |
| `items` | 读取物品变换、`box` 或 `compound` 碰撞体、接口局部坐标和接口类型 |
| `obstacles`、`reserved_zones` | 路径和线缆体积的禁入体积；产品走线传空 `reserved_zones`，独立领域输入仍尊重显式禁入区 |
| `exposure_zones` | 计算当前路径和原始路径的桌面暴露弧长 |
| `routing_graph` | 提供按策略过滤的允许节点和通道边 |
| `cables` | 连接端点、线缆类型、线径、可关闭的物理最小弯曲半径、线长、余量和策略 |

`regions`、`desk` 等字段仍由入口结构校验读取；它们不参与路线搜索时不能被算法忽略。算法不读取 `model_url`、`generation` 等外观字段。

线缆请求沿用数据契约中的完整字段，不添加世界坐标端点：

```json
{
  "id": "cable_laptop_power",
  "start_port_id": "laptop_power",
  "end_port_id": "pdu_socket_1",
  "cable_type": "power",
  "thickness": "thin",
  "length_m": 1.8,
  "diameter_m": 0.004,
  "min_bend_radius_m": 0.02,
  "slack_m": 0.08,
  "mode": "slot"
}
```

### 2.2 入口校验

入口校验失败时不进入搜索。布局与走线共同复用 `backend/app/domain/rules.py` 校验协议版本、完整结构、有限数值、全局唯一 ID 与引用，走线另要求所连接口已确认。缺字段、不能表示为有限浮点数的极大整数和不可表示的物品世界碰撞体均通过带 `field` 的 `RoutingInputError` 拒绝，不泄漏 `KeyError` 或 `OverflowError`。后端负责映射这些错误；算法对单条线缆的语义失败使用数据契约中的 `reason_code`。

校验顺序固定为：

1. 检查 `schema_version == "1.0"`、场景 ID/版本存在，所有坐标和尺寸为有限数，已知线长和直径为正数，最小弯曲半径与余量为非负数；线长可为 `null`。
2. 建立物品、接口、图节点、图边、线缆的唯一 ID 索引，检查所有引用存在。
3. 按 `position + R_y(rotation_y_rad) * local_position` 计算接口世界坐标，按同一旋转矩阵变换 `local_direction`，并归一化方向。接口坐标不得使用模型包围盒中心替代底面中心。
4. 检查端口类型与 `cable_type` 兼容，统计每个端口在本次请求中的占用数，不超过 `capacity`。插排孔按独立端口处理，总线端口不能代替插孔。
5. 检查请求的 `mode` 是 `slot` 或 `backboard`，并确认图中存在对应边。`slot` 路径必须有实际 `kind: "slot"` 节点；`backboard` 路径必须有背板后的 `fixing_point` 节点和相应边，否则返回 `unsupported_mode`，不自动切换策略。
6. 检查每条边的端点存在、`modes` 非空、`clearance_radius_m` 大于零；边的直线几何仍需在搜索和最终曲线验证时重新检查，不能把配置视为免检。

### 2.3 算法内部的规范化对象

Python 模块内部使用类型化对象，不作为新的网络 JSON：

- `ResolvedEndpoint`：`port_id`、所属物品 ID、世界位置、世界朝外方向、碰撞体引用。
- `CableSpec`：线缆 ID、端口、模式、线径、最小弯曲半径、可用长度和线缆半径 `diameter_m / 2`。
- `RoutingEdge`：图边几何、允许模式、通道半径、暴露提示、相邻节点。
- `OccupiedTube`：已经成功规划的线缆曲线及其半径，用于后续汇聚检查。

所有内部几何仍使用米制右手 Y-up 世界坐标，几何容差沿用 `0.001m`。规范化阶段不复制或改名外部字段。

## 3. 搜索策略

### 3.1 采用 A*，保留 Dijkstra 作为等价调试路径

首版使用 A* 搜索每条线缆的策略子图。启发式为当前节点到目标端点的欧氏距离，这是非负边代价下的可采纳下界。搜索将到目标接口的最后连接和引入段计入完整终点代价，只有完整目标状态出队时才结束，避免在较近图节点提前停止。相同代价函数下与 Dijkstra 得到相同最优代价，并提供 `use_dijkstra=True` 开关及终点连接代价回归。

图边代价只包含非负项：

```text
edge_cost = length
          + exposure_penalty * (exposed ? length : 0)
          + bend_penalty * estimated_turn
          + unsupported_penalty * unsupported_length_upper_bound
```

`exposed` 只是搜索偏好，最终暴露线长必须按 `exposure_zones` 的曲线弧长计算。当前权重为 exposure 3.0（原为 0.2）、bend 0.03、unsupported 3.0；产品将桌后缘并排通道标为非暴露边，使其优先于横穿桌面的捷径。该标记不能用来减少最终几何统计值，也不表示后缘已经安装固定件。无支撑代价在开启策略时覆盖两端连接及有限引出段。权重在算法内固定，不写入场景协议；纯领域函数不写运行日志。节点 ID 作为平局排序键，保证相同输入得到稳定结果。

每条线缆的图搜索过程如下：

1. 按 `mode` 过滤边，并为端口建立有限数量的候选引出边。`box` 的引出段沿接口朝外方向到膨胀 OBB 的首出口；`compound` 识别包含接口的部件，或在接口紧贴外壳外侧时识别法向正后方最近的壳体，其余部件仍会挡线，具体范围与余量见[数据契约](data_contract.md#22-区域与碰撞几何)。只豁免曲线首尾落在有限直线通道内的连续段；其余段、其他物品、障碍及本次请求的禁入区仍逐段扫掠检查，不能整体忽略设备碰撞体。
2. 先做边级净空和禁入体积检查。线缆半径加几何容差必须小于边的 `clearance_radius_m`；与 `obstacles` 或 `reserved_zones` 相交的边直接排除。开启支撑策略后，边与端点连接中单独超过跨距上限的候选也排除；边级检查不能代替完整曲线复查。
3. 在过滤后的图上运行 A*，得到端点到端点的节点折线。路径必须满足对应策略的拓扑条件：穿线孔策略实际穿过 `slot` 节点，背板后策略实际到达背板后固定点再下行。
4. 对折线做去重和共线点简化，保留端点、模式关键节点和线缆汇聚所需的几何点。

### 3.2 多线缆汇聚与有界重规划

多线缆使用“受限优先规划”，首版不引入全局多商品流求解器：

1. 先按可行引出候选数升序、线径降序、线缆 ID 升序排序；越难连接、越粗的线优先。
2. 每成功一条线，就把其验证曲线登记为 `OccupiedTube`。后续线缆可以共用通道，但必须在通道横截面内分配不同中心位置，满足两条线中心距 `>= (d1 + d2) / 2 + 0.001m`，并且所有中心位置都在 `clearance_radius_m` 内。
3. 每轮中，正数半径线缆最多进行 3 次路径搜索；零半径线缆先对 40mm、20mm 法向引出各搜索 1 次，再对原外壳引出最多搜索 3 次，每线最多 5 次。每次均对曲线及有界局部候选复查。发生线间冲突时先尝试通道内侧移；仍失败则禁用该路径的一条图边，后续搜索同时避开已占用线缆。正数半径或混合半径请求只规划一轮；全部线缆均为零半径、且仅部分线缆以 `no_path` 失败时，最多将失败线优先重算整组 1 次，仅在有效线缆更多时采纳第二组完整结果，不混合两轮路径。
4. 无路可搜或达到尝试上限后返回明确失败原因，不无限重试或把重叠中心线标记为有效汇聚。通道空间或净空不足返回 `no_path`；端口容量超限（含直插关系占用后再次连接）返回 `port_occupied`。线长、支撑或接口引出受阻等失败保留对应的 `length_exceeded`、`unsupported_span` 或 `endpoint_blocked`，失败路径为空。

### 3.3 逐线规划后的可选集线槽优化

先完成所有线缆的独立路线及线间避让，再由 `routing/optimizer.py` 分析最终曲线。已安装托盘仍是正常支撑；待安装的 `tray_candidates` 只供优化阶段读取，不参与前面的路径搜索和支撑判定。优化保留原有路径、长度和成功/失败状态，不能让候选托盘使原本失败的路线变成有效。

在配置的桌底安装范围内，寻找至少两根有效线的平行、连续共享区段，按线径与曲线误差内缩范围后用控制凸包保守确认；纵向重叠不足 0.15m 的零散接触不推荐。输出共用纵向长度、现有路线占用的横向宽度、可用宽度及安装位置；这些数值描述收束机会，不表示线长减少。交叉线、无共享区段、超出槽范围或未成功的线不强行合并。

每个候选最多推荐一个组合，优先成员数，再比较共用长度；未入组的线路保持原方案。该阶段不保证全局最优，计算预算不足时返回未评估，不推造可安装结论。

候选不可用时保留逐线方案。产品面板显示后端返回的成员、共享长度和未采用原因；用户单独确认安装，配置作为场景编辑同步后，才将候选转为已安装支撑、递增版本并重算。支撑复核开关默认关闭，关闭时不报告安装可行性已验证。参数和结果字段见[数据契约](data_contract.md#25-可选集线槽优化)；真实安装及完整指南步骤仍需验收。

## 4. 曲线生成与连续几何验证

搜索结果是用于避障的折线，不能直接作为最终线缆。曲线生成和验证必须使用同一批控制点与采样点：

1. `min_bend_radius_m > 0` 时，在每个折线转角两侧按该值截取切线段并生成圆角过渡；相邻边长度不足以容纳最小半径时，该候选路径失败并换下一条。为 `0` 时不施加该物理最小值，使用有限数量的小圆角及局部控制柄候选适配紧凑桌沿，仍生成连续曲线，不把未经复查的尖角折线直接标为成功。
2. 将直线段和圆角段编码为三次 Bézier 段。段间端点重合、切向连续，首尾控制点固定为真实接口世界坐标；无转角的直线使用共线控制点。共享通道的侧向偏移按各段端点速度修正控制点，使汇聚后的相邻段仍保持切向连续；复查同时拒绝端点重合但接缝带尖角的分段曲线。
3. 自适应采样每段曲线，弦高误差不超过 `0.0005m`，弦长不超过 `0.01m`；正数最小半径另外将弦长限制在该值的 `1/8`。`path_points` 只能来自这些采样点。
4. 对同一曲线执行以下验证：
   - 端点位置与接口世界坐标误差不超过 `0.001m`，解析控制柄切向与起点朝外法向、终点反向法向一致；
   - 用曲线扫掠半径检查 `obstacles`、`reserved_zones`、设备碰撞体和已占用线缆管，不只检查离散点；
   - 正数 `min_bend_radius_m` 使用 Bézier 导数与自适应细分复查连续曲率，最小曲率半径不得小于该值；为 `0` 时不做物理最小曲率判定，仍复查段间连续性与接口切向；
   - 用同一曲线做自适应弧长积分，计算所需备线长度 `path_length_m + slack_m`；仅在 `length_m` 非 `null` 时检查该长度不超过现有线长，未知线长不阻止规划，也不跳过其他复查；
   - 重新确认模式关键节点和通道净空仍被曲线覆盖。

曲线平滑后任何一项失败，都不能输出平滑前的折线作为成功结果；应尝试下一条搜索路径，耗尽上限后返回 `no_path`、`collision` 或 `length_exceeded` 等最具体原因。

端口连接到较远图节点时，按整段长度生成的朝外控制柄可能过度鼓起。正数半径保留原曲线优先，验证失败后最多再尝试两个由端点曲率约束推导的局部控制柄候选；零半径使用有界的小圆角候选。每个候选仍完整复查接口切向、碰撞、通道、线间净空、长度及已启用的曲率/支撑条件，不增加上述路径搜索次数：每轮正数线最多 3 次、零半径线最多 5 次；正数半径或混合请求仅一轮，全零且部分 `no_path` 失败时最多重算整组 1 次。

首轮曲线及侧向偏移都不可行时，后续搜索同时排除被已验证线缆占用的图边和端口连接段，允许选择配置中的并行通道。重试的支撑诊断也保留同一占用条件，避免将线间冲突误报为缺少支撑。最终曲线仍需重新校验线间净空，图中绕开占用本身不代表成功。

显示采样用 Bézier 控制凸包到有限弦段的最大距离作保守误差界，并同时限制弦长；碰撞扫掠另加 `0.0005m` 采样误差余量。S 形曲线不能仅凭中点共线而跳过细分，达到细分预算仍无法满足误差时返回空采样并判定路线失败。

物品碰撞在候选计数、图边搜索、端点引出和最终扫掠中使用同一份 `collision`。`compound` 对每个凸体的面法向做双侧支持平面裁剪，并保守膨胀平面容纳线缆半径与误差；不会把显示器支架或收纳盒的空隙封成整体包围盒。平面投影范围缓存复用，世界旋转与平移先应用于部件。空隙可通行并不代表有固定支撑，支撑仍只来自显式安装配置。

### 4.1 连续支撑复查

支撑检查位于 `backend/app/domain/routing/support.py`。由障碍安装面、切向范围及离面量建立外侧 AABB 带，再按线缆半径和 0.0005m 误差余量内缩。Bézier 的四个控制点全部位于同一内缩带内，才能借助凸包证明该段连续受支撑；否则自适应细分。未证明受支撑的部分按控制多边形长度上界累计，连续跨距跨越 Bézier 接缝累积，零长度支撑点不能重置跨距。

细分深度上限 18、总细分次数上限 32768、长度分辨率 0.00001m；达到预算仍需继续细分时判定失败。最终平滑和多线汇聚侧移后的曲线均重新执行该检查，不能仅验证图节点或折线。返回支撑证据只表示通过配置的几何约束，不模拟下垂、受力或固定件承载。

无支撑跨距不满足要求时返回 `unsupported_span`，失败路径为空。诊断搜索与支撑搜索使用相同的临时禁边集合，避免将弯曲等其他候选失败误报为支撑不足。候选尝试次数仍有限，不保证找到所有可能的可行曲线。

## 5. 暴露线长计算

对每条有效曲线，按 `exposure_zones` 的 AABB 并集裁剪同一条 Bézier 曲线，累加位于并集内的弧长，得到 `metrics.exposed_length_m`。该指标不使用 `routing_graph.edges[].exposed` 代替几何计算。

若输入提供某条线缆的 `baseline_path_points`，用同一裁剪和弧长规则计算基线；只要有一条请求线缆缺少基线，`baseline_exposed_length_m` 就为 `null`，不能按零或按当前路径补齐。没有任何有效当前路径时，当前暴露线长也为 `null`。B 汇总时只对已知数值计算差值或比例。

## 6. 输出与失败语义

算法输出一个可 JSON 序列化的 `cable_routing.json`，覆盖全部请求线缆，并原样携带输入 `scene_id`、`scene_revision`：

```json
{
  "schema_version": "1.0",
  "scene_id": "scene_demo",
  "scene_revision": 4,
  "status": "partial",
  "cables": [
    {
      "id": "cable_laptop_power",
      "start_port_id": "laptop_power",
      "end_port_id": "pdu_socket_1",
      "cable_type": "power",
      "thickness": "thin",
      "mode": "slot",
      "diameter_m": 0.004,
      "status": "valid",
      "curve_segments": [
        {"control_points": [[0.90,0.79,0.32],[0.86,0.79,0.32],[0.82,0.78,0.30],[0.78,0.78,0.30]]}
      ],
      "path_points": [[0.90,0.79,0.32],[0.84,0.785,0.3075],[0.78,0.78,0.30]],
      "path_length_m": 0.13,
      "reason_code": null
    }
  ],
  "metrics": {
    "exposed_length_m": 0.08,
    "baseline_exposed_length_m": null
  },
  "issues": []
}
```

单条失败时 `curve_segments`、`path_points` 为空，`path_length_m` 为 `null`，并填写一个已有错误码。顶层状态规则沿用数据契约：全部 `valid` 为 `success`，部分有效为 `partial`，全部失败为 `infeasible`。`unsupported_mode`、`invalid_input` 等原因不能伪装成备用策略成功。

前端只绘制算法返回的 `path_points`；若需要从 `curve_segments` 重建，必须使用数据契约规定的三次 Bézier 定义和同一采样精度，不能自行拟合另一条曲线。

## 7. 后端调用边界

当前纯函数入口位于领域包，后端直接调用：

```python
from backend.app.domain.routing import RoutingInputError, plan_routing

result = plan_routing(scene)
```

`plan_routes` 与 `plan_routing` 指向同一函数，原 `algorithm.cable_routing` 及其 `planner`、`geometry` 模块只重新导出领域对象。`Scene`、`RoutingResult` 和 `Issue` 等类型位于 `domain/models.py`。函数不修改传入对象，不写文件，不调用前端或 Rodin。B 负责保存请求、检查结果版本、应用有效结果和生成指南；D 只负责规划、几何验证、指标和 `issues`。结果版本与输入一致。

`validate_routing(scene, result)` 与 `measure_exposed_length(scene, result=None)` 两个独立入口尚未实现。当前曲线复查和暴露线长计算由规划函数内部执行，不等于已提供可供保存结果、指南独立复用的接口。后端 `RoutingService` 已经在统一装配中复用正式场景、SQLite、受限执行器与版本条件保存，产品通过该服务规划全部当前线缆；这不替代上述独立复查入口及完整流程验收。

运行算法与兼容性回归：

```sh
python3 -B -m unittest discover -s backend/tests -v
python3 -B -m unittest discover -s algorithm/cable_routing/tests -v
ruff check backend algorithm
```

`backend/tests/test_domain_boundaries.py` 在隔离 Python 子进程中仅加载复制的领域包，封锁旧算法包、Web、数据库、网络与供应商导入，并在算法运行期间禁止文件、网络及 SQLite I/O。完整共同场景可执行布局、模拟应用后递增版本、复查、面积和三条走线调用；旧包的全部公开入口也逐项核对为领域对象。该测试未运行服务装配或真实通道联调，失败走线仍按失败输出。

## 8. 实施顺序与验收样例

建议按以下顺序实现，每步都保留可独立运行的 JSON 样例：

1. 端口世界坐标、线缆类型/容量校验和单条直线路径。
2. `slot` 图搜索、引出段、A* 与失败原因。
3. Bézier 圆角、采样、弧长、弯曲半径和扫掠碰撞复查。
4. `backboard` 独立图搜索，验证同一端点产生与 `slot` 不同的有效路径。
5. 4/6/8 位插排端口分配、粗细线参数和两条以上线缆的通道汇聚。
6. 暴露线长、版本过期、线长不足、接口遮挡、通道过窄和策略缺失案例。

最低验收集包括：两种策略各一条成功样例；3 根线含插排总线、4 位插排和多线汇聚；粗线/细线的真实线径及净空、零半径产品请求和正数半径领域回归；移动物品后端点随旋转更新；每一种失败原因都没有残留有效路径；布局应用后递增版本并能在新版本重新规划。

复合碰撞回归位于 `backend/tests/test_routing_compound.py`，覆盖显示器支架空隙的 A* / Dijkstra、Y 轴旋转、实体与不足净空阻挡、单部件端口引出、邻近独立部件不被豁免、外部端口、自身再入、平滑曲线碰撞及正反方向平面裁剪。旧 `box` 输入继续保留兼容检查；这些几何样例不代表真实 GLB 或后端服务联调已通过。
