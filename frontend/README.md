# DormTopology 3D 前端（成员 A）

React + TypeScript + Three.js（React Three Fiber + Drei）实现的宿舍桌面整理与理线应用。物品整理、理线与遗留布局请求固定交给应用后端，网页不再提供规则演示规划或模式切换。真实整理支持正式场景、基线、版本、后台任务与原子应用；真实理线在确认接口后，对当前全部线缆规划并验证几何，计算所需线长，保留失败原因且拒绝过期结果，无需输入实际线长。`VITE_API_MODE=mock`（默认）仅让识别和 Rodin 使用单独标注的模拟数据；`real` 请求尚未实现的供应商应用接口时会返回真实错误，遗留布局端点也仍为 HTTP 501。最终页按原始快照与当前场景生成逐件整理动画。契约与运行方式见 [docs/api-integration.md](docs/api-integration.md)。

产品走线优先沿桌面后缘的并排通道，粗细线只影响实际线径、碰撞与净空，不设置物理最小转弯半径；打字、水杯与腿部活动区只约束物品摆放。工作台可添加桌后理线扣、桌下扎带和集线槽，分别确认安装并随项目保存；支撑跨距复核默认关闭，开启后才导出已安装配件与真实桌面支撑。待安装集线槽独立作为汇聚候选，不补足当前支撑。

推荐整理默认传 `constraints.min_item_gap_m: 0.02`，对真实物品部件的水平净距进行后端及前端复查，并保留穿线孔上方出线空间；间距不足结果不可应用，历史候选恢复和接受请求发送前同样复查。历史领域场景省略约束仍兼容，已有摆放不会自动搬动；手动编辑的间距在下一次推荐与接受时复查，原始布局恢复及撤销重做保留原状态语义。

独立的 `/algorithm-lab` 可读取真实 Python 领域算法导出的 JSON，查看布局、路径和失败原因；这不代表产品流程或 Rodin 真实联调已完成。

当前视觉与布局基线见 [DESIGN.md](../DESIGN.md)，本轮实现与截图见 [UI 改版记录](docs/ui-refresh/README.md)；旧设计草案保留于 [docs/design-spec.md](docs/design-spec.md)；仓库级约定以 [实施方案](../docs/implementation_roadmap.md) 与 [数据契约](../docs/data_contract.md) 为准。

## 已实现的流程（后端整理与理线）

项目列表 → 创建项目（命名、空间、物品）→ 自动载入工作台 → 整理动画。

- **示例导览**：6 步固定顺序（查看凌乱桌面 → 确认识别物品 → 自动整理 → 规划走线 → 对比前后 → 查看整理动画），步骤切换自动导航、完成自动打勾、可点步骤条跳转；重播重新种入示例项目并清理交付勾选 / 候选方案 / 任务记录 / 撤销历史；导览进度本地持久化；工作台步骤自动切换桌面视角。导览中的整理与理线同样请求后端，模拟等待加速仅影响识别与模型生成；系统「减少动态效果」偏好可让整理 / 收拢动画直接显示末态。历史演示脚本与验收明细见 [docs/demo-and-acceptance.md](docs/demo-and-acceptance.md)。

- **整理操作演示**：方案编译为逐件模型移动 / 旋转指令，自动播放、暂停、重播与最终效果；实现边界与检查见 [整理操作演示](docs/organization-playback.md)。

- **空间配置**（`/projects/:id/setup`）：床桌 / 房间 / 立柱 / 书架 / 出线孔为固定标准模型（0.9.0 起不再提供尺寸编辑，正式模型资产接入中），只调整后墙插座左右位置；表单为毫米制（与三维内部米制通过 `@/lib/units` 换算），配置冲突有就地校验；墙面插座为一块「双插孔 ×2」面板，仅沿后墙左右移动（高度固定 350mm，滑块 + 数值），变更后相关走线提示需重算。
- **照片导入**（`/projects/:id/import`）：示例照片与上传（IndexedDB 保存）、识别 Mock 输出候选清单、物品增删改与尺寸确认、模型生成任务 Mock（等待/失败/重试/部分成功）、物品落位到桌面。
- **三维工作台**（`/projects/:id/workspace`）：
  - 独立表面描点（`/projects/:id/objects/:objectId/ports`，电脑端）：右键物品进入只展示该模型的页面，旋转/缩放、正面/背面/顶面取点，保存接口局部坐标。可保存并返回工作台；确认接口后以此点开始连线。保留场景布局与当前撤销历史。
  - 场景与交互：固定家具加载 `dormdesk_parts/` 四份 GLB，共享支撑与碰撞几何；失败自动回退同源简化家具并可重试，工具栏可显示 / 隐藏；相机预设、选择、支撑面吸附、旋转与数值编辑、摆放校验及撤销重做。
  - 空间整理：后端布局算法预览（前后对比、归位动画、接受/取消），接受时由后端复查并原子应用；失败保留原因与当前布局。
  - 走线规划：设备接口编辑（局部偏移/朝向/类型及独立确认）、两点连线、线缆列表与属性、路径节点编辑、原始/建议对比及收拢动画。新建与改接共用自连、重复、兼容性和单端口容量检查。规划须确认当前尺寸、位置及引用接口，固定调用后端 Python 双策略搜索及连续曲线验证；无需输入实际线长，按路径与预留显示所需备线长度。已有数据中的实际线长继续参与长度不足校验。单线更新也全量重规划，以共同检查接口占用和线间碰撞。
  - 走线结果与失效：真实有效曲线按后端采样点直接绘制，使用后端积分长度，不再二次平滑；失败结果无有效路径，部分失败时总长显示未知。物品或障碍的移动、旋转、尺寸、增删、接口、空间配置及连接参数变化会使旧结果失效；异步返回前核对输入和正式版本，旧结果不覆盖新编辑。手动改路径、撤销和重做需重新验证。
  - 理线配件：桌后理线扣、桌下扎带和集线槽预设来自真实桌板，初始为待安装建议，可确认安装、删除、撤销与重做，位置随三维场景显示。支撑跨距复核默认关闭，开启后仅将确认安装的配件与真实桌面用于支撑检查。候选集线槽在逐线规划后显示可合并成员、共享长度及未采用原因，不自动安装或改变路线有效性。配件、安装状态和支撑参数的编辑使旧走线与指南失效，过期集线槽结果隐藏；界面确认不代替实体安装验收。
  - 插排与线材（0.7.0）：插排规格可选 4/6/8 位（孔间距 / 最大建议负载可配，随项目保存），支持拖拽移动与「放到桌下横梁」，切换规格时弹窗列出受影响连接、被移除孔位的连接标「冲突」并提示改插（不静默删除）；线缆区分**可见线**（经桌面出线槽）与**隐藏线**（经背板后），按设备名自动推断、手动可改，类型不匹配时提示「按新类型重新规划」并保留原路径；粗 / 细线径两档真实改变渲染半径，间距建议为咨询级提示（不阻断规划）。
  - 按住查看摆放前，松开恢复；更多菜单可保存及恢复历史方案，旧方案数据保留。
  - 拖动允许干涉并提醒，尺寸输入与 Ctrl 角点缩放拒绝碰撞；Q/E 每次旋转 10°；支撑面、边缘与近邻自动吸附。
  - 抽屉旁柜门可开合，柜内上下两层可吸附摆放；预制笔记本默认朝座位。右键进入单模型表面描点页面。
- **整理动画**（`/projects/:id/result`）：根据原始快照与当前摆放逐件演示，可播放、暂停、前后步骤和重播，并按住前后对比。失效路径不显示为有效连接，摆放冲突继续提醒；缺少基线或没有变化时如实说明。产品移除执行指南与并排方案比较；旧 `guide`、`compare` 路由兼容进入动画页。

不伪造精确比例与算法结论：整理与理线固定调用后端，结果仍须通过身份、版本和几何校验；失败显示实际原因并可重试。识别与模型生成的模拟数据单独标记，未接入能力如实失败，页面不提供规划演示模式切换（契约与限制见 [docs/api-integration.md](docs/api-integration.md)）。

## 与仓库数据契约的已知差异（联调前需解决）

当前演示应用的内部约定与[数据契约](../docs/data_contract.md)存在以下差异；联调时在 `api/` 层转换或按契约调整，避免直接以内部模型充当 wire format：

1. **坐标系原点**：产品前端以家具横向中心、后墙为参考；`dormdesk-v1` 到算法/API 平移 `[0.45,0,-0.042]`，历史参数化项目保留 `[desk.width/2,0,-0.05]`。局部碰撞和端口不重复转换；完整资产变换见[桌体说明](docs/desk-model.md)。
2. **演示尺寸**：当前产品示例桌包络为 1.45 × 0.86 × 0.75 m、14 件物品、7 根线，支撑为实际 L 形桌面。种子 v7 移除三本演示书籍，已有 v6 示例仅删除这些物品及关联连线，保留其他位置和接口编辑；笔记本与手机使用适配器的独立 USB 输出，适配器另接插排 AC 输入，暂不包含插排至墙插的总线。独立算法共同场景 `demo_desk_v1` 为 1.45 × 0.60 × 0.77 m、8 件待整理物品。整理发送当前实际配置，不强制改成另一模板；完整比赛场景验收仍按任务清单进行。
3. **字段命名**：内部领域类型为 camelCase（`types/project.ts`），契约 JSON 为 snake_case（`scene.json` / `packing_result.json` / `cable_routing.json`）；`api/` 层负责双向转换。
4. **接口与线缆模型**：真实走线由 `routingWire.ts` 导出完整当前场景、确认接口、单端口容量、实际线长、预留、粗细线径与双策略网络，并解析统一失败原因。产品统一传 `min_bend_radius_m: 0` 与 `reserved_zones: []`；正数半径和显式禁入区的独立领域输入仍按契约检查。USB-A/C 映射为契约 USB，AC/DC 按供电与受电语义映射。旧 `toWireScenePayload` 不用于领域走线。真实整理由 `packingWire.ts` 导出布局场景，线缆和走线网络为空；详见[接入说明](docs/api-integration.md)。
5. **结果状态语义**：契约使用 `success/partial/infeasible`、`valid/failed` 与统一 `reason_code`；本应用内部状态（planned/stale/conflict 等）仅用于本地展示，需在 `api/` 层映射。
6. **算法来源**：整理固定由 FastAPI 调用 `backend/app/domain/packing` 并原子应用，走线固定通过后台任务调用 `backend/app/domain/routing`，任务结果与布局应用分开。旧浏览器模式及规划环境变量不再选择本地规则算法；独立算法工作台继续使用离线 JSON。
7. **新增算法字段**：真实整理已导出大型显示器、打印机的 `placement_priority`。产品已支持配件配置与安装确认，开启支撑复核才导出 `supports` / `support_policy`，未安装集线槽独立导出为 `tray_candidates`；`plug_mount` 的产品编辑与应用仍未接入。墙面设备默认高度 350mm 与共享契约 0.30m 的差异也仍待统一。
