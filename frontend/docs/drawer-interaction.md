# 抽屉推拉（桌柜分离模型）交互设计

> 状态（2026-10-17）：**设计稿，待「桌子和抽屉分离」模型到位后实现**。
> 背景：现有 `dormdesk.glb` 已含三抽屉侧柜（`Cabinet_Drawer_{Bot,Mid,Top}_*`），但为静态几何、无动画；
> 用户已预告将提供「桌子和抽屉分离」的模型。本文定义模型命名 / extras 契约、前端运动学方案、
> 交互与数据设计、验收口径，供评审后实施。

## 1. 为什么需要「分离」模型（现状问题）

- 现有模型里抽屉面板与柜体侧面、盒体共用接触面；**直接平移拉出会露出共面内部的穿帮**
  （面板内侧没有完整几何、滑出后面板与柜体交接处可能 z-fighting / 内部可见）。
- 分离模型可以为每只抽屉提供完整的独立几何（盒体内外侧、面板、拉手槽、滑轨），
  拉出时视图自然；同时让前端能以「命名节点 + 契约」稳定地建立运动学。
- 结论：**推拉交互以实现为前提的模型契约先给到建模同学**（第 2 节），前端实现不等几何细节齐备（第 3–6 节）。

## 2. 模型侧契约（给建模同学的清单）

### 2.1 节点结构

每只抽屉的全部部件挂到一个**具名空父节点（Pivot）**下：

```
Drawer_Bot_Pivot            ← 空物体（无网格），Pivot 原点 = 滑出行程起点（全闭时）
  ├─ Cabinet_Drawer_Bot_Box        （盒体，保留现有命名）
  ├─ Cabinet_Drawer_Bot_Front      （面板）
  ├─ Cabinet_Drawer_Bot_PullGroove （拉手槽）
  ├─ Cabinet_Drawer_Bot_Rail_L     （滑轨）
  └─ Cabinet_Drawer_Bot_Rail_R
Drawer_Mid_Pivot   …
Drawer_Top_Pivot   …
```

- 槽位命名：`Bot / Mid / Top`（与现有一致；id 落为 `bot / mid / top`）。
- 子部件命名沿用现有 `Cabinet_Drawer_<Slot>_*`，前端不做改名。
- Pivot 的**局部 +x 方向 = 滑出方向**（现有模型为 app 坐标 -x 拉出；导出时按局部轴折算，
  前端只认 Pivot 局部轴，不再关心世界方向）。
- Pivot 位置固定在全闭状态，抽屉的运动学由前端修改 `pivot.position` 完成；**不要**把行程预烘焙进几何。

### 2.2 行程与吸附（glTF `extras`，可选但推荐）

在 Pivot 节点的 `extras` 中声明滑出行程（three 的 GLTFLoader 会读入 `object.userData`）：

```json
{
  "slide": {
    "axis": "+x",          // 局部轴，支持 +/- x/y/z
    "min": 0,
    "max": 0.30,           // 全开行程（米）
    "snap": [0, 0.30],     // 吸附点（默认 [min, max]）
    "label": "下层抽屉"     // 可选，用于无障碍 / 提示文案
  }
}
```

**无 extras 时的前端回退**（自动推导，保证旧模型也能跑）：
- 轴向：取 Pivot 内盒体包围盒的最长水平轴（现有模型为 x）；
- `max` = 盒体沿轴长度 0.30 m − 面板厚度 0.018 m − 2 cm 重叠余量 ≈ 0.26 m；
- `snap` = `[0, max]`。
- 契约校验扩展：`scripts/check-desk-model.ts` 增加「三只 Pivot + 子节点齐全 + extras 合法（0 ≤ min < max ≤ 盒体深度）」断言。

### 2.3 备选方案：烘焙动画（不推荐为首选）

可以在 Blender 烘焙 `Drawer_*_Open` 单轴动画，前端用 `AnimationMixer` 以进度驱动。
放弃原因：拖拽交互需要任意进度控制与吸附点数据；动画方案难以做「半开」「受阻限位」，
且不同方案快照共用同一模型时会互相干扰。若建模侧已有动画，可作为无 extras 时的第二回退（前端换算为 `max`）。

## 3. 前端运行时方案（推荐：节点分组 + 运动学滑动）

### 3.1 加载与注册

`scene/dormDeskDrawers.ts`（新模块，纯计算可单测）：

1. 在 `mountDeskModel` 之后扫描模型：匹配 `/^drawer_(\w+)_pivot$/i` 的节点，读 `userData.slide`（或回退推导）；
2. 记录 `DrawerRegistry: { id, pivot, axis: Vector3（Pivot 局部轴→root 坐标）, min, max, snap, label }[]`；
3. 无分离模型时（仅旧 `Cabinet_Drawer_*` 命名）：可按前缀现场聚合重建 Pivot（`Box+Front+PullGroove+Rail_*` 组），
   跑通「单击开 / 关」最小功能；出料即升级为 2.1 契约。
4. 注册结果放 `state/drawerStore.ts`（zustand，会话态）。

### 3.2 状态与动画

- `drawerStore`：`{ [id]: { progress: number; target: 0 | 1; dragging: boolean } }`；
  **不持久化**（开合是视图状态，刷新后回到全闭；见第 5 节数据口径）。
- 动画：每帧 `progress → target` 指数缓动（~220 ms 收敛），`pivot.position = axis * lerp(min, max, progress)`；
  无物理引擎（与首版「不做刚体」的边界一致），硬限位由 `clamp` 保证。

### 3.3 交互（桌面 + 移动端）

| 操作 | 行为 |
| --- | --- |
| 悬停 | 抽屉面板 / 拉手槽高亮（描边 + `cursor: grab`）；raycast 仅命中抽屉组 |
| 拖拽 | 按下进入抽屉拖拽：把指针位移投影到滑出轴（屏幕像素 → 轴上的最近点参数，与现有 `useObjectDrag` 的投影同口径）；`progress = clamp(0..1)` 实时跟手 |
| 松手 | 吸附：`progress ≥ 0.5` → 全开，否则全关（带缓动）；支持「甩开」（可选，按松手速度给初速度） |
| 单击（位移 < 4 px） | 开 / 关切换——移动端主路径（无 hover） |
| Esc / 空白点击 | 拖拽取消 → 回弹到最近的 snap 点 |
| 相机 | 拖拽期间锁定 orbit（复用现有交互锁机制），松手恢复 |

### 3.4 阻挡与冲突（分两步）

- **v1（先上线）**：不做物理阻挡；全开时若与外部物体（如椅子）相交，显示轻提示
  「抽屉全开可能与××相碰」，不阻断操作。
- **v2（可选）**：开启方向做 AABB 扫掠（抽屉盒体的包围盒 + 位移 × progress）与场景物体求交，
  受阻时把 `max` 动态钳制到受阻前 1 cm 并提示；仅当物品可动时允许自动推开（不实现）。

## 4. 抽屉内容物（与整理 / 收纳的衔接）

1. **收纳语义**：三只抽屉是「固定收纳区域」（对应 AGENTS.md 首版验收的右侧抽屉）。
   后续物品整理 / 打包可以把物品安置到 `drawer-bot / drawer-mid / drawer-top` 区域。
2. **跟随渲染**：物品数据仍保存**全闭时的基准位置**；渲染时按当前 `progress` 给箱内物品加
   `axis * lerp(min, max, progress)` 的增量偏移（在 `SceneObjectMesh` 叠一层视图偏移），
   不移动数据坐标 → 方案快照 / 算法载荷保持稳定。
3. **遮挡**：全闭时抽屉面板自然遮住内部物品；开启时可见。无需额外处理。
4. **边界**：物品尺寸超出抽屉内腔时由既有摆放校验拦截（按区域内腔尺寸），不在本交互内处理。

## 5. 数据口径（什么进数据、什么不进）

| 内容 | 存储位置 | 说明 |
| --- | --- | --- |
| 抽屉开合进度 / 拖拽中 | `drawerStore`（会话） | 视图状态，不持久化、不进方案快照 |
| 物品「在抽屉内」 | `SceneObject`（既有收纳 / 区域归属语义） | 进方案快照与算法载荷 |
| 抽屉行程 / 吸附点 | 模型 `extras`（或前端推导） | 资产契约，不入项目数据 |

## 6. 验收（实现轮的目标）

- **脚本（Node / tsx）**：注册表生成（3 只抽屉、轴 / 行程 / 回退推导）、`progress` 钳制与吸附边界、
  拖拽投影单调性（纯函数）——保持与 `check-*` 家族一致的直跑风格。
- **Playwright（桌面 + 模拟手机）**：单击开 / 关后画布像素差异非零；拖拽到 60% 后吸附全开；
  Esc 取消回弹；拖拽期间相机不旋转（对比拖拽前后截图相机参数不变）。
- **契约**：`check-desk-model.ts` 的抽屉 Pivot / extras 断言（分离模型到位后启用）。

## 7. 里程碑

1. **M1（分离模型到位）**：Pivot + extras 接入，单击开 / 关 + 契约校验（最小可用）。
2. **M2**：拖拽投影 + 相机锁 + 移动端单击 + Esc 回弹（完整交互）。
3. **M3**：物品入抽屉（整理 / 打包接入区域）+ 跟随渲染。
4. **M4（可选）**：阻挡检测 v2 与提示细化。

> 与固定模型轮次的关系：M1 依赖用户提供「桌子和抽屉分离模型」；此前如需演示，
> 可先用现有模型按 3.1-④ 现场聚合试跑（注明为近似，不对外承诺手感）。
